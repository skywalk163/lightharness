E-01	test_事件循环.light	事件循环	0	FreeBSD 就绪派发顺序差异：断言「同挂时先派发读」实际=写（非 socketpair 崩溃；R86-B 已修族映射，此为残余断言差异）。【R88-B 根因】kqueue 对同一 fd 上同时挂起的读/写就绪事件，出列顺序与 epoll/select 不同：本测试 test_事件循环.light §5 钉死「先读后写」，FreeBSD kqueue 先报写就绪 → 序列首位=写。属后端就绪队列顺序语义差异，非逻辑错误；改测试顺序断言会削弱 Linux/Windows 既有语义覆盖，按豁免固化。
E-02	test_套接字.light	TCP/UDP 回环	0	FreeBSD 回环 send 阻塞超时（stdlib/套接字.light:207 发送全部）；R86-B 已修族映射/OPT 级别，此为残余时序差异。【R88-B 根因】test_套接字.light §7 用 2.0s 套接字超时连发 200KB（b"A"*200000），发送全部 循环在 stdlib/套接字.light:207 反复阻塞写；FreeBSD 回环 TCP 窗口/接收排空节奏比 Linux/Windows 慢，发送缓冲未排空前 send 阻塞超过 2.0s 预算 → 超时异常。属固定 2s 预算在 FreeBSD 回环上偏紧的计时差异，非收发逻辑错误。
E-06	test_进程树接线.light	沙箱超时	0	断言失败: 沙箱秒数上限触发超时 实际=False 期望=True（FreeBSD 沙箱超时判定差异）。【R88-B 根因】test_进程树接线.light §6 沙箱 秒数上限=1 跑 `ping -n 30`；FreeBSD 沙箱把「秒数上限」落到 RLIMIT_CPU（CPU 时间），而 ping 阻塞在 recvmsg 等 ICMP 回包、几乎不耗 CPU → 1s CPU 上限永不触发；Linux/Windows 沙箱用挂钟看门狗到点强杀。属资源上限口径（CPU 时间 vs 挂钟）基线差异。
