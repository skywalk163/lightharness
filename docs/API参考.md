# API 参考

本文档列出 lightharness 各模块的公开接口。当前版本覆盖遥测模块。

---

## 遥测收集器（遥测.light）

### 构造

```light
设 遥测 为 新建 遥测收集器()
```

创建一个新的遥测收集器实例。所有属性初始化为默认值。

**参数：** 无

**返回值：** `遥测收集器` 实例

---

### 开始会话

```light
设 span 为 遥测.开始会话(会话ID)
```

开始一个会话级 span（kind=`session`），生成 trace_id，压入 span 栈。

**参数：**
- `会话ID`（字符串）：会话标识

**返回值：** span 字典 `{trace_id, span_id, parent_span_id, name, kind, start_time, end_time, duration_ms, attributes, status, error_message}`

**示例：**
```light
设 会话span 为 遥测.开始会话("sess_001")
打印 会话span["trace_id"]
```

---

### 开始轮次

```light
设 span 为 遥测.开始轮次()
```

开始一个轮次级 span（kind=`turn`），父 span 为当前栈顶。

**参数：** 无

**返回值：** span 字典

---

### 开始步骤

```light
设 span 为 遥测.开始步骤()
```

开始一个步骤级 span（kind=`step`），父 span 为当前栈顶。

**参数：** 无

**返回值：** span 字典

---

### 记录LLM调用

```light
设 span 为 遥测.记录LLM调用(模型, TTFT毫秒, 输入tokens, 输出tokens, 缓存tokens, 完成原因)
```

记录一次 LLM 调用，创建 kind=`llm` 的 span（不压栈，立即结束）。

**参数：**
- `模型`（字符串）：模型名称，如 `"deepseek-chat"`
- `TTFT毫秒`（数值）：首 token 延迟（Time To First Token）
- `输入tokens`（整数）：输入 token 数
- `输出tokens`（整数）：输出 token 数
- `缓存tokens`（整数）：缓存读取 token 数
- `完成原因`（字符串）：如 `"stop"` / `"tool_calls"` / `"max_tokens"`

**返回值：** span 字典，attributes 包含 `model, ttft_ms, input_tokens, output_tokens, cache_read_tokens, finish_reason`

**示例：**
```light
设 llmspan 为 遥测.记录LLM调用("deepseek-chat", 120.5, 500, 200, 50, "stop")
断言等于(llmspan["attributes"]["model"], "deepseek-chat")
```

---

### 记录工具调用详情

```light
设 span 为 遥测.记录工具调用详情(工具名, 参数hash, 成功, 错误类型)
```

记录一次工具调用，创建 kind=`tool` 的 span（不压栈，立即结束）。注意：此为新签名方法，旧方法 `记录工具调用(工具名, 延迟秒)` 仍保留用于向后兼容。

**参数：**
- `工具名`（字符串）：工具名称
- `参数hash`（字符串）：参数的哈希值（用于隐私保护，不记录参数正文）
- `成功`（布尔）：是否调用成功
- `错误类型`（字符串）：失败时的错误类型，如 `"timeout"` / `"auth"` / `"network"`

**返回值：** span 字典，attributes 包含 `tool_name, params_hash, success, error_type`

**示例：**
```light
设 toolspan 为 遥测.记录工具调用详情("bash", "abc123", 真, "")
断言等于(toolspan["status"], "ok")
```

---

### 结束当前

```light
设 span 为 遥测.结束当前()
```

结束栈顶 span，设置 `end_time` 和 `duration_ms`，弹出栈。

**参数：** 无

**返回值：** 已结束的 span 字典；栈为空时返回 `空`

**示例：**
```light
遥测.开始会话("s1")
遥测.开始轮次()
遥测.开始步骤()
遥测.结束当前()  # 结束 step
遥测.结束当前()  # 结束 turn
遥测.结束当前()  # 结束 session
```

---

### 聚合统计

```light
设 结果 为 遥测.聚合统计(维度)
```

按指定维度聚合统计。

**参数：**
- `维度`（字符串）：`"轮次"` / `"步骤"` / `"模型"` / `"工具"`

**返回值：**
- 轮次/步骤维度：`{维度, 调用数, 总耗时, 平均耗时, 成功率, 错误数}`
- 模型/工具维度：`{维度, 分组: {键: {调用数, 总耗时, 平均耗时, 成功率}}}`

**示例：**
```light
设 模型聚合 为 遥测.聚合统计("模型")
设 分组 为 模型聚合["分组"]
设 项 为 分组["deepseek-chat"]
打印 项["调用数"]  # 1
打印 项["成功率"]  # 1.0
```

## 遥测输出器（遥测导出器.light）

### 输出器基类接口

所有输出器实现以下接口：

| 方法 | 说明 |
|------|------|
| `输出(spans)` | 输出 span 列表 |
| `输出指标(metrics)` | 输出指标数据 |
| `刷新()` | 刷新缓冲区 |
| `关闭()` | 关闭输出器 |

---

### 控制台输出器

```light
设 输出器 为 新建 控制台输出器(选项)
```

将 span 格式化输出到控制台。

**构造参数：**
- `选项`（字典，可选）：支持 `capture_content`（布尔，默认 `假`）

**方法：**
- `输出(spans)`：打印每个 span 的 kind/name/span_id/parent/耗时/状态，返回 span 数量
- `输出指标(metrics)`：打印指标数据
- `过滤(span)`：隐私过滤，返回过滤后的 span（`capture_content=false` 时移除正文字段）

**示例：**
```light
设 输出器 为 新建 控制台输出器(空)
设 数量 为 输出器.输出(全部span)
```

---

### JSONL输出器

```light
设 输出器 为 新建 JSONL输出器(文件路径, 选项)
```

将 span 以 JSONL 格式写入文件（每行一个 span）。

**构造参数：**
- `文件路径`（字符串）：输出文件路径
- `选项`（字典，可选）：支持 `capture_content`

**方法：**
- `输出(spans)`：写入文件，返回 span 数量
- `输出指标(metrics)`：将指标写入 `{文件路径}.metrics.json`
- `过滤(span)`：隐私过滤

**示例：**
```light
设 输出器 为 新建 JSONL输出器("./telemetry/s1.jsonl", 空)
输出器.输出(全部span)
```

---

### OTLP输出器（接口层预留）

```light
设 输出器 为 新建 OTLP输出器(端点, 请求头, 选项)
```

OTLP（OpenTelemetry Protocol）导出器。当前为接口层预留，仅组装 OTLP HTTP 请求结构，不实际发送网络请求。

**构造参数：**
- `端点`（字符串）：OTLP HTTP 端点 URL
- `请求头`（字典）：HTTP 请求头，如 `["Authorization": "Bearer xxx"]`
- `选项`（字典，可选）：支持 `capture_content`

**方法：**
- `输出(spans)`：组装 OTLP 请求体，返回 `{endpoint, headers, format, resource_spans, 注意}`，打印预留提示
- `输出指标(metrics)`：组装指标请求体
- `过滤(span)`：隐私过滤

**示例：**
```light
设 输出器 为 新建 OTLP输出器("https://otlp.example.com/v1/traces", ["Authorization": "Bearer xxx"], 空)
设 请求体 为 输出器.输出(全部span)
打印 请求体["注意"]  # "OTLP输出为接口层预留，未实际发送HTTP请求"
```

---

### 输出器管理器

```light
设 管理器 为 新建 输出器管理器()
```

管理多个输出器，广播输出到所有已注册输出器。

**方法：**
- `注册(输出器)`：注册一个输出器，返回当前输出器数量
- `输出(spans)`：广播输出到所有注册输出器，返回 `[{名称, 结果}]` 列表
- `输出指标(metrics)`：广播输出指标
- `刷新()`：刷新所有输出器
- `关闭()`：关闭所有输出器

**示例：**
```light
设 管理器 为 新建 输出器管理器()
管理器.注册(新建 控制台输出器(空))
管理器.注册(新建 JSONL输出器("./out.jsonl", 空))
设 结果 为 管理器.输出(全部span)  # 同时输出到控制台和文件
管理器.关闭()
```

## Span 数据结构

每个 span 是一个字典，包含以下字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `trace_id` | 字符串 | 追踪 ID（会话级生成，全链路唯一） |
| `span_id` | 字符串 | span ID（每个 span 唯一） |
| `parent_span_id` | 字符串 | 父 span ID（会话级为空字符串） |
| `name` | 字符串 | span 名称，如 `"session:sess_001"` / `"turn"` / `"llm:deepseek-chat"` |
| `kind` | 字符串 | 类型：`session` / `turn` / `step` / `llm` / `tool` |
| `start_time` | 数值 | 开始时间戳（秒） |
| `end_time` | 数值 | 结束时间戳（秒） |
| `duration_ms` | 数值 | 持续时间（毫秒） |
| `attributes` | 字典 | 附加属性（LLM/工具 span 含详细指标） |
| `status` | 字符串 | 状态：`"ok"` / `"error"` |
| `error_message` | 字符串 | 错误信息（成功时为空） |

### LLM span attributes

| 字段 | 说明 |
|------|------|
| `model` | 模型名称 |
| `ttft_ms` | 首 token 延迟（毫秒） |
| `input_tokens` | 输入 token 数 |
| `output_tokens` | 输出 token 数 |
| `cache_read_tokens` | 缓存读取 token 数 |
| `finish_reason` | 完成原因 |

### 工具 span attributes

| 字段 | 说明 |
|------|------|
| `tool_name` | 工具名称 |
| `params_hash` | 参数哈希（隐私保护） |
| `success` | 是否成功（布尔） |
| `error_type` | 错误类型 |

## Web HTTP API（新会话落地页，T-0395~T-0399）

服务入口见 `src/web服务器.light`。下表的键名是**字面量**，请求/响应都用 UTF-8 JSON。
`<根>` 指会话持久化根（`Web服务端.根`）。

### POST /api/sessions —— 新建会话

请求体（全部字段可选；空体 / 坏 JSON 仍按旧行为建会话）：

```json
{"标题": "新会话", "工作目录": "/abs/dir", "模式": "ptc", "权限预设": "全放行"}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `标题` | 字符串 | 空/缺省 → `"新会话"` |
| `工作目录` | 字符串 | **绝对路径**，必须是已存在且可读的目录；缺省 = 回退全局工作目录（旧行为） |
| `模式` | 字符串 | 以 `预设清单()` 为准：`standard` / `ptc` / `minimal` / `cordis` / `topdown` / `bottomup` / `brainstorm` / `lazy`；非法值静默丢弃（不报错） |
| `权限预设` | 字符串 | `全放行` / `按类别` / `全拒绝` / `自定义`（四个值**都会**落 `session-modes.json` 并原样回读）；非法值静默丢弃 |

响应 `200`：会话元数据 `{id, 标题, 创建时间, 最后更新, 消息数, 文件, 工作目录?}`。
`400`：`工作目录` 不存在 / 是文件 / 是相对路径（**不建会话、不写索引**），响应体带中文理由。

### GET /api/cwd/check —— 目录只读校验

查询参数（四选一，键也接受 URL 编码）：`工作目录` / `路径` / `path` / `cwd`。

```bash
curl "http://127.0.0.1:8787/api/cwd/check?工作目录=%2Fhome%2Fme%2Fproj"
```

响应恒为 `200`：

```json
{"存在": true, "是目录": true, "可读": true, "绝对路径": "/home/me/proj", "错误": ""}
```

- 相对路径按**服务进程 cwd** 解析，并在 `绝对路径` 回显；
- 失败时 `错误` 给中文理由（不存在 / 不是目录 / 不可读），其余布尔为 `false`；
- **红线**：本端点只读——不改进程 cwd、不写 `settings.json`；与 `POST /api/cwd`（会 chdir + 落盘）是两条实现。

### GET /api/sessions/current —— 当前会话

查询参数 `?session=<id>`（或用认证令牌绑定的会话）。响应 = 会话元数据 + 三键：

| 键 | 说明 |
| --- | --- |
| `工作目录` | 该会话自己的 cwd（缺省时该键不存在，读侧回退全局） |
| `模式` | 会话级模式；无会话级设置时为 `""` |
| `权限预设` | 会话级权限预设；无会话级设置时为 `""`（生效值回退全局默认 `按类别`） |

`400` 未指定会话（不带 `?session=` 且该令牌没绑定过会话）；`404` 会话不存在。

**选会话的优先级**：显式 `?session=` **优先**；只有在没写 `?session=` 时，才回落到
认证令牌的「令牌 → 会话」绑定（该绑定 = 这个令牌**最近一次**新建的会话）。
所以带令牌 + `?session=<id>` 拿到的就是 `<id>` 那个会话；指到不存在的会话返回 `404`，
不会悄悄换成令牌绑定的那个。

> T-0408 修掉了此前的反序（曾先看令牌绑定、忽略 `?session=`，导致多会话下
> 带令牌问旧会话恒回最新那个，前端 `refreshSessionTitle()` 把标题刷成别的会话的）。
> 正向判据：`tests/test_T0408_会话读取三个缺陷.py::test_带令牌_current优先用session参数`
> 与 `tests/test_T0399_新会话对齐.py::test_current带令牌尊重session参数`。

> 注：**切回会话的 cwd/模式/权限并不读这个端点**。前端 `selectSession()` 走的是
> `GET /api/sessions/<id>`（见下节），那是「切回恢复」的真正数据通路。

### GET /api/sessions/:id —— 会话详情

```json
{"id": "...", "模型": "mock", "工作目录": "/abs/dir", "模式": "ptc", "权限预设": "全放行", "消息": [...]}
```

`工作目录`/`模式`/`权限预设` 三键为 T-0395/T-0397 新增（只增不改，侧边栏/导出依赖的旧键形状不变）。

### POST /api/sessions/:id/模式权限 —— 会话内切换

```json
{"模式": "minimal", "权限预设": "全拒绝"}
```

只改**该会话**（不动其它会话与全局 `权限管理器`）；只传一个键时另一键保持原值；显式空串 = 回到全局默认。
非法预设 → `400`（响应体带中文理由，如 `未知 agent preset: nope`）。

响应 `200`：`{"ok": 1, "模式": "<切换后>", "权限预设": "<切换后>"}`（回显的是该会话**当前**的生效设置，
不是本次请求体）。路径中的 `<id>` 与 `/模式权限` 都允许百分号编码（浏览器 fetch 会自动编码中文）；
非 POST 方法落到同一个前缀的兜底分支 → `404`。

### POST /v1/chat/completions —— 新增可选字段

在既有 OpenAI 兼容入参上新增（都可缺省，缺省 = 旧行为）：

| 字段 | 说明 |
| --- | --- |
| `preset` | 本轮 Agent 预设；同时按会话写回 `模式` |
| `权限预设` | 本轮权限预设；按会话写回（续轮不带 = 保留已存值） |
| `工作目录` | **首条**消息惰性建会话时的 cwd；非法目录 → `400` |
| `attachments` | 前端 best-effort 上送 `[{name, type, dataUrl}]`；**服务端当前不消费**（只保证不打断首条消息落库），形状属协议既有面，勿改 |

每轮结束后，会话记录里的四键 `工作目录 / 模式 / 权限预设 / 模型` 可通过
`GET /api/sessions/:id` 读回；切回旧会话时前端据此还原。

#### 落库的消息形状与一个已知缺口

`GET /api/sessions/:id` 的 `消息` 数组由每轮结束时的落库写入，角色有四种：
`user` / `assistant` / `tool-call` / `tool-result`。后两者 `内容` 是**序列化后的字符串**：

```json
{"角色": "tool-call",   "内容": "{\"工具名\": \"读文件\", \"参数\": \"{...}\", \"调用id\": \"c1\", \"轮次\": 1}"}
{"角色": "tool-result", "内容": "{\"工具名\": \"读文件\", \"结果\": \"{\\\"内容\\\":\\\"...\\\"}\", \"错误\": \"\", \"是否错误\": false, \"调用id\": \"c1\"}"}
```

`tool-result` 的 `结果` 是工具输出的可读正文：落库路径与 SSE 同口径，会下钻
`{type:"tool-result", content:[{type:"text", text:...}]}` 取子块 `text`，
并按 `源序号` 关联 `tool/call` 回填 `工具名`、从块的 `toolCallId` 回填 `调用id`
（T-0408 修复前这里恒为空串，会话重放看不到工具输出）。
判据：`tests/test_T0408_会话读取三个缺陷.py::test_工具结果正文落库且有工具名`
与 `tests/test_T0399_新会话对齐.py::test_tool_result消息正文落库`。

#### 流式（`stream: true`）下的差异

流式路径的持久化只写 `user` + `assistant` 两条，**不写** `tool-call` / `tool-result`；
非流式路径才会写全四种角色。流式请求里出现的工具调用仍会照常执行、也会进事件层 JSONL，
只是 `GET /api/sessions/:id` 的 `消息` 里看不到。前端工具卡片依赖的是 SSE 帧而非这个端点，
所以 UI 上不受影响；**如果你在写脚本按 `消息` 判工具执行，请用非流式请求。**

### 命令面：`/goal` 与 `/compact`（T-0407）

两个命令都**不是独立路由**，而是 `POST /v1/chat/completions` 里用户消息正文的前缀：
服务端 `去除空白` 后按前缀识别，识别后不再把命令字样交给模型。

**`/goal <目标描述>`**

- 空描述 → `400`，体为 `用法：/goal <目标描述>`；
- 描述本身作为**首轮用户文本**发给模型，同时给该会话建一个 goal 台账；
- 同一请求进入 `当` 循环：每轮结束按 `续续跑决策` 决定「续跑 / 完成 / 停止」；
  续跑上限默认 **8 轮**，连续 **2 轮无进展**即停；
- `目标` 工具只在「本会话有目标」时注册，不污染其它会话的工具集；
- 统计帧的 `轮次数` 就是本次 HTTP 请求真实跑过的轮数（续跑会让它 > 1）。

**`/compact`**

- 服务端命令：**不调模型、不消耗轮次**，直接走 `压缩策略.压判断触发(入口=手动)`
  + `压缩.light.压缩到最近`，随后回「压缩」事件帧；
- 会话正忙 → `409`，体为压缩不可用原因 + 排队提示文案；
- 普通回包与 SSE 都会带压缩帧；前端「上下文 xx% / 压缩」按钮复用的就是这条通道。

### 命令面：`/plan`（T-0420）

`/plan` 与 `/goal`、`/compact` 一样是正文前缀命令，**不调模型、不消耗轮次**：

- `/plan`、`/plan on` → 开计划模式；`/plan off` → 关；其它参数 → `400`，体为 `用法：/plan 或 /plan off`；
- 会话正忙 → `409`，体为 `会话运行中：等本轮结束再切换计划模式`；
- 开关会落三类事件：`command/run`（`name:"plan"`、`commandId`、`args`）、
  `command/done`（`kind:"success"`）、`plan/mode`（`active`），重启后按事件折出状态；
- 回执：流式先发一帧 `data: {"种类":"计划","plan":{...}}` 再 `data: [DONE]`；
  非流式回 `{"状态":"ok","会话":"<id>","plan":{...}}`（首轮没带 `session_id` 时用 `会话` 绑定）。
  `plan` 对象为 `{active,pending,text,title}`；
- 开启后本轮多挂一个 `exit_plan_mode` 工具（`plan` 必填、`title` 可选）。
  调用成功 → 落 `plan/mode(active=false)` + `plan/submitted{plan,title}`，
  回包 `concludesTurn:true` 结束本轮；计划正文在后续对话里仍可作为上文继续讨论；
- `GET /api/sessions/current` 与 `GET /api/sessions/:id` 新增 `计划` 键（同一 `plan` 形状）；
- 与 `topdown` 模式**不再耦合**：`topdown` 只是提示词人格，计划模式只认会话事件。

### 忙时排队与插话（202 / 429 / 409）

同一会话已有请求在跑时，`POST /v1/chat/completions` 按下面分流（判定键 = 实际会话 id）：

| 请求 | 状态码 | 响应体 |
| --- | --- | --- |
| 普通消息 | `202` | `{"状态":"排队","位置":N,"会话":"<id>","深度":N,"上限":N}` |
| 队列满（默认 8） | `429` | `{"状态":"拒绝","理由":"队列已满"}` |
| 带 `X-LH-Interrupt: 1` | `202` | `{"状态":"插话","位置":N,"会话":"<id>"}` |
| 插话满（默认 4） | `429` | `{"状态":"拒绝","理由":"插话已满"}` |
| `/compact` | `409` | 压缩不可用原因 + 排队提示文案 |
| `/plan` | `409` | `会话运行中：等本轮结束再切换计划模式` |

- 队列与插话由「持锁的那一轮」在轮末消费：**先续跑，再插话，最后出队**，共用一个 `当` 循环，
  不另起线程；
- 占用归属：非流式请求在 `处理对话` 拿、流式请求在 `推流实现` 发第一帧时拿并在 `最终` 释放；
  直调处理器且不消费流的自测**不占位**（保留旧的串行 200 行为）；
- 闸门是**每进程单例**：同一进程内同会话串行；多进程 / 多实例各排各的，跨进程不互见。

### 统计帧新增字段（T-0407）

`种类:"统计"` 帧在原有 6 键上追加：

| 键 | 类型 | 说明 |
| --- | --- | --- |
| `开始时刻` | 浮点 | Unix 秒，本请求首轮开始 |
| `完成时刻` | 浮点 | Unix 秒，本轮结束 |
| `耗时秒` | 浮点 | 完成 − 开始 |
| `速率` | 整数 | 输出 token / 耗时秒（耗时为 0 或负 → 0） |
| `轮次数` | 整数 | 本请求实际跑过的轮数（续跑/排队会 > 1） |

前端顶栏用前四个做实时计时与 `tok/s`，`轮次数` 用于「续跑真的跑了 2 轮」这类判据。

### 会话索引 `完成时间`（T-0407）

`会话存储.记完成时间(存储, 标识, 时刻)` 在索引元数据里**只增**一个 `"完成时间"`（ISO 串），
`创建时间 / 最后更新 / 消息数 / 文件` 原样不动；旧会话没有该键时读回 `""`，不报错、不迁移。
