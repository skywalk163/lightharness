## 二、`调用事件表` 那条为什么会出现、又为什么还在

- 根因：E2 会话持久化段用了 `调用事件表`/`结果事件表` 两张表，但这俩原先只在 `生成SSE`
  函数内部定义。改造后新增的分支直接引用，作用域里没有 → `NameError` → 外层
  `捕获 异常` 包成 `处理对话异常: ...` 返回 500。
- 现状：源码 508–510 行已经补了 `设 调用事件表 / 结果事件表 为 会话对象.查询事件(...)`，
  并且注释也写明了这条历史报错。**这条现在已经不会再报。**

但它只是「打地鼠」里的一只。真正让流式请求必崩的，是下面三处。

## 三、本次实际修复的 3 处必崩接线错误

改造把链路从「跑完整轮 → 一次性发 SSE」改成「边跑边推」，新增了 `造流式响应`、
`后台跑一轮`、`推流实现`、`实时流.light`、`HTTPPost流式` 等一堆零件，但接线没接全：

1. **漏导入（NameError 的真正根源）**
   `造流式响应`/`推流实现` 用到 `实时队列`、`编码SSE帧`、`流块转增量帧`、`线程`、
   `流发送` 五个符号，而 `web服务器.light` 顶层一个都没导入。
   → 任何 `stream=true` 请求一进来就 `NameError`。语法检查抓不到，只有运行时才炸。
   **修**：`web服务器.light` 头部补 4 条导入。

2. **载具缺 `服务` 键（KeyError）**
   `后台跑一轮` 读 `载具["服务"]` 去拿 `服务.根` / `服务.会话库`，但 `造流式响应`
   构造载具时没放这个键。
   **修**：载具和响应字典都补上 `"服务": 己`。

3. **回调实参/形参不一致（TypeError）**
   `HTTP服务端.light` 只调 `响应["流响应"](流发送器)`（1 参），而 `推流实现`
   声明了 `(发送器, 载具, 服务)`（3 参）。典型的契约漂移。
   **修**：HTTP 层调用补传 `响应["载具"]`、`响应["服务"]`。

### 改动文件
- `src/web服务器.light` — 补导入、载具/响应带服务键
- `stdlib/HTTP服务端.light` — 流响应调用补两个实参
- `tests/test_流式推流接线契约.py` — 新增，5 项静态契约断言（防复发）

## 五、追加：交付后又断连（16:20）—— chunked 长度进制错误

**现象**：提交推送后用户反馈「一对话就断开」，前端提示
`连接中断：已保留已接收的内容，请重试。`

**根因**：`stdlib/HTTP服务端.light` 的 `构造分块` 把 chunk size 写成了**十进制**：
```light
# 错误
返回 转字符串(长(字节)).encode("utf-8") + b"\r\n" + 字节 + b"\r\n"
```
HTTP chunked 编码（RFC 7230）要求 size 是**十六进制 ASCII**。十进制在长度 <10 时
与十六进制恰好相同能跑通；一旦某帧字节数 ≥10（SSE 帧 `data: {...}\n\n` 通常上百字节，
中文按 UTF-8 每字 3 字节更容易触发），浏览器按十六进制解读十进制数字 → 分块边界错位 →
流读取中途抛 `TypeError` → 前端 catch 到 `started=true` 分支，显示「连接中断」。

**修法**：
```light
设 长度十六进制 为 hex(长(字节))[2:]   # hex(n) 返回 "0xa"，[2:] 去掉前缀
返回 长度十六进制.encode("utf-8") + b"\r\n" + 字节 + b"\r\n"
```
（`hex` 是编译器内置，生成码里 `hex = builtins.hex`；`[2:]` 切片语法编译通过。）

**验证**：
- 新增 `tests/test_HTTP分块十六进制.py`（2 项）：静态断言源码用 `hex(n)[2:]`；
  6 组样本（长度 1/10/15/16/100 + 真实中文 SSE 帧）走标准 chunked 解码器往返全通过。
- 端到端：mock 模式起 `examples/运行Web服务器.light`（端口 44051），真实发
  `stream=true` 请求 → `STATUS 200` / `TRANSFER-ENCODING: chunked` / 收到 `[DONE]` /
  `RESULT_OK`，服务端日志无异常，未再断连。
- 两批测试合计 7 passed。
