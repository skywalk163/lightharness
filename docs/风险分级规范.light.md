# 工具可逆性风险分级规范（reversibility，T-0508）

这份文档只解决一件事：**给工具注册表一个统一、可复核的「不可逆性」口径**。

在这之前，守卫的表述是各写各的：`write_file` 覆盖要求「先读」、`edit_file` 要求「唯一命中」、
`bash` 的 delete/move 有「先验证绝对路径」要求，而批量类工具（`todo_write`、`预设删除`、
`注册钩子` 一族）的不可逆风险提示偏弱。根因不是文案，而是 registry 里没有一张统一的
「这个动作改完能不能回滚」的表。本规范定这张表；**分级只是元数据，不改执行行为**。

落点：

| 内容 | 文件 | 段落 |
|---|---|---|
| 四级常量 / 逐名分级表 / 纯函数 / 注册接口回填 | `src/工具面装配.light` | `§11 可逆性（reversibility）风险分级` |
| 判据（判分脚本） | `tests/test_T0508_可逆性分级.py` | 四个 test |
| 域元数据（同级机制） | `src/工具面装配.light` / `src/工具执行.light` | `§9 能力域（domain）元数据` / `按域列工具`、`工具之域` |

---

## 0. 消费者与边界

消费方是守卫/确认流程（提示文案、二次确认、只读判定），接线在 **T-0509（静态分级的守卫接线）**
与 **T-0510（bash/SSH 高危命令的动态判定）**。本规范阶段只保证：

1. 每个已注册工具都有确定档位，且判定理由写得出（逐名表 + 本节判定标准）；
2. 按档位可查询、可枚举、可统计，回填幂等；
3. **分级本身不改变任何执行路径**——不改 `处理`、不改权限级别、不改 wire 名与参数签名。

反向也成立：**不准只靠分级去改行为**。守卫要「拦」一个动作，必须同时改提示/确认与判据，
不能只在表里把一档写成 `irreversible` 就宣称拦住了。

---

## 1. 四级定义

分级看三个维度：**能不能回滚**（有无明确回滚路径）、**影响面**（自己产物 / 用户已有数据 / 外部世界）、
**要不要先确认**（默认是否人工点头）。

| 级别 | 字面值 | 判定标准（三条全中才算） | 回滚路径 | 影响面 | 默认确认 | 典型工具 |
|---|---|---|---|---|---|---|
| 只读 | `read_only` | 不改任何持久状态；同一输入重复执行结果一致 | 无需回滚 | 仅读取 | 不需要 | `读文件`、`搜索文件`、`获取环境变量`、`待办列出`、`web_fetch`、`风险判定` |
| 可逆 | `reversible` | 有明确回滚路径（撤销/取消/删除本次新增的产物），且不覆盖既有数据 | 一键撤销或删本人产物 | 仅新增/登记 | 不需要（可提示） | `创建会话`、`切换会话`、`待办添加`、`提醒注册`/`提醒取消`、`登记产物`、`附件上传`、`图片生成` |
| 半可逆 | `semi` | 能恢复，但需要**额外步骤或人工介入**；或存在覆盖同名产物的风险 | 重放/重新下载/人工找回 | 局部，可能覆盖同域产物 | 建议确认（看影响面） | `压缩摘要`、`录音控制`、`LSP发请求`、`附件下载`、`工作线程运行时` |
| 不可逆 | `irreversible` | 无回滚路径：删除、覆盖、外发、进程/外部世界动作 | 无 | 用户既有数据 / 外部世界 | 必须确认 | `写文件`、`编辑文件`、`todo_write`、`待办删除`、`预设保存`/`预设删除`、`bash`、`Webhook触发`、`屏幕操作` |

三条口径写死，避免各人各判：

- **覆盖即不可逆**：目标已存在同名内容时，覆盖后原内容无备份 → 不可逆。所以 `写文件`、`预设保存`、
  `存储写入`、`凭据存入`、`写入设置`、`设置环境变量` 全部落在 `irreversible`，
  哪怕它们「只是写一个值」。
- **新增即先按可逆**：只产生新条目/新文件、不触碰既有内容的（`待办添加`、`登记产物`、`图片生成`、
  `附件上传`），回滚 = 删除本次产物 → `reversible`；一旦带「覆盖同名」风险就降档到 `semi`（`附件下载`）。
- **状态机往前推进不可逆**：把状态从 A 改到 B 且没有回退 API 的（`待办完成`、`目标推进`、`计划开始`/
  `计划完成`/`计划阻塞`、`反馈处理`），一律 `irreversible`；只是「登记/创建」的则 `reversible`。

## 2. 判定流程（三步，可复核）

`工具可逆性(工具名)` 的优先级，与 `工具域(工具名)` 完全同构：

1. **逐名分级表**（`可逆性表`，168 条）：命中即返回该档。表是唯一真相，改一行只影响一个工具。
2. **MCP 透传**（`mcp__<服务器>__<工具>`）：远端副作用本仓不可知 → 恒 `irreversible`，
   不进静态表（工具集随 `mcp.json` 变化）。
3. **缺省兜底**：未登记名 / 非字符串 / 空串 → `默认可逆性` = `irreversible`（**fail-closed**）。

为什么逐名而不是按前缀：同一个动词前缀会跨档——`写入缓冲`（可回滚）/ `写入设置`（覆盖）/
`写入终端`（外发）。T-0496 的 domain 能用前缀规则兜底，是因为「域」错一档只是分类不准；
「可逆性」错一档会让守卫漏拦，所以逐名落表。

`是否显式分级(工具名)` 的口径：表内命中 = 真；MCP = 真（有文档化兜底规则）；其余 = 假。
`未分级工具(名表)` 就是抓漏的探针，本卡实测 `168 / 未分级 0`。

## 3. 静态分级 vs 动态判定

命令内容决定风险，静态表给不出逐条命令的档位。本卡只定**静态最坏情形**：

| 工具 | 静态档位 | 动态细化归属 |
|---|---|---|
| `bash` | `irreversible` | T-0510：`rm`/`mv`/重定向覆盖/`git reset --hard` 等按命令内容判；纯读命令（`ls`/`cat`/`grep`）可降到 `read_only` |
| `SSH执行` | `irreversible` | T-0510：同 `bash` 口径，另外「目标机不可回滚」单独加权 |
| `执行Python脚本` | `irreversible` | T-0510：脚本内容不可静态判定，保持最坏情形 |

原则：**静态档位只许比动态判定更严，不许更宽**。守卫拿不到动态结论时按静态档位走，
宁可多问一句；拿到了动态结论可以降档，但降档必须留审计。

## 4. 边界案例（逐条给理由，便于 review 时反驳）

| 工具 | 档位 | 理由 |
|---|---|---|
| `写文件` | `irreversible` | 覆盖同名文件，无备份；「先读」只是降低误覆盖概率，不构成回滚路径 |
| `编辑文件` | `irreversible` | 原地改写，「唯一命中」保证改对地方，不保证改得回 |
| `todo_write` | `irreversible` | 整表覆盖：一次调用可静默丢掉多条已有待办，是批量工具里风险最高的一档 |
| `待办删除` / `预设删除` / `Webhook删除` / `存储删除` / `凭据删除` | `irreversible` | 删完没有回收站，也没有版本历史 |
| `预设保存` | `irreversible` | 同名预设被整体替换，旧配置无副本 |
| `待办完成` | `irreversible` | 状态迁移，无「取消完成」接口 |
| `切换会话` / `创建会话` | `reversible` | 会话可再切回/删除；不动用户既有数据 |
| `提醒取消` / `释放任务槽` | `reversible` | 取消类动作本身可再注册，属「撤销」而非「销毁」 |
| `压缩摘要` | `semi` | 原文已被摘要替换；靠重放会话能恢复，但要额外步骤 |
| `附件下载` | `semi` | 写本地文件；同名覆盖需人工找回 |
| `附件上传` | `reversible` | 只新增远端副本，可删 |
| `present` | `read_only` | 只做展示，不改任何状态（不算「外发」：内容未离开本机会话） |
| `Webhook触发` / `提醒触发` | `irreversible` | 消息已出网，本仓无法撤回 |
| `屏幕操作` / `桌面驱动CUA*` / `浏览器驱动*` / `执行动作队列` | `irreversible` | 点一下就落到外部世界（提交、发送、购买），无回滚 |
| `目标推进` | `irreversible` | 推进即消耗轮次与副作用，无回退 API（`目标创建` 才是 `reversible`） |
| `skill` / `技能取用` | `read_only` | 只载入技能正文，不改状态 |

## 5. 注册接口与回填

复用 T-0496 的**同一个**注册接口，不另造机制：分级挂在 `建注册表()` / `具注册工具()`
写出的同一个「工具表」条目上，字段名 `"可逆性"`，与 `"域"` 并列。

| 函数（`src/工具面装配.light` §11.3） | 语义 |
|---|---|
| `工具可逆性(名)` | 纯查表：显式表 → MCP → 缺省；永远返回四级之一，不抛错 |
| `是否显式分级(名)` | 表内命中/MCP = 真；未知 = 假 |
| `按可逆性取工具(名表, 级)` | 按档取子集，保持入参（登记）顺序；未知档返回空表 |
| `未分级工具(名表)` | 回填漏网探针 |
| `可逆性统计(名表)` | `{read_only, reversible, semi, irreversible, 未分级}` |
| `附可逆性(注册, 名)` | 在注册表条目上补 `"可逆性"` 字段；未登记/注册非字典 → 空 |
| `补可逆性(注册)` | 遍历注册表批量补字段，幂等，返回补的条数 |
| `工具之可逆性(注册, 名)` | 读条目已回填的档位；没回填则按名回退静态分级 |

已知限制（如实登记）：`具注册工具` 本体在 `src/工具执行.light`，不在 T-0508 的允许路径内，
且它已反向 `import` 本模块，再加依赖会成环。故本卡不新增它的参数槽位，只提供
`附可逆性` / `补可逆性` 两个回填入口；把参数槽位接进 `具注册工具` 归 T-0509/T-0510 的接线卡。

## 6. 接线（T-0509）：分级 → 执行前确认门控

分级本身是纯元数据，**真正拦人的是执行前门控**：`src/工具执行.light` §7c 的 `具分级守卫`
在权限判定、参数校验之后、限流与处理器之前执行，同步 / 异步 / 并发三条入口同判。
策略表本体在 `src/工具面装配.light` §11.4（`门控动作` / `工具门控判定` / `造门控配置`）。

### 6.1 四档动作（强度递增）

| 动作 | 执行器行为 |
|---|---|
| `放行` | 零拦截。只读与合法可逆调用走这一档，**误拦率为零是硬约束** |
| `提示` | 放行 + 门控日志留痕（软守卫，不改结果形状） |
| `校验` | 强制前置校验，通过则放行并留痕，不通过即拒绝 |
| `确认` | 前置校验 → §7 预决确认出口（ask → 审批链收敛；**无审批通道 = deny**） |

### 6.2 默认映射（保守）

| 分级 | 默认动作 | 理由 |
|---|---|---|
| `read_only` | 放行 | 不改状态 |
| `reversible` | 放行 | 有明确回滚路径 |
| `semi` | 提示 | 需要额外步骤/人工才能回滚，先留痕 |
| `irreversible` | 确认 | 无回滚路径，必须先确认 |
| 未显式分级（插件/自造工具） | 提示 | 不误拦未知工具，但留痕可追 |
| 缺档 / 非法档 | 确认 | 不确定时偏向确认而非放行 |

### 6.3 可配覆盖

`造门控配置(覆盖表)` 按档覆盖策略（如 `irreversible → 校验` 放宽为「强制校验即放行」），
也接受 `未分级` / `缺档` 两个键；**非法动作值一律忽略**，不会把配置写成非法态。
配置经 `建执行器` 第 8 参注入；缺省 / 非字典一律回落默认策略，不抛错。

### 6.4 前置校验（只对不可逆档跑，复用 `工具_路径安全`）

1. **文件类**：写 / 编辑的目标必须在工具根内（`解析安全路径`，与处理器同口径）；
2. **命令类**：`rm` / `mv` 的每个目标都要解析到工具根内（`校验破坏性命令目标`）；
3. **覆盖前先读**：写文件且目标已存在、又不在本执行器「已读清单」里 → 拒绝（审批放行也不跳）。

### 6.5 动态降档（静态只许更严；降档必留日志）

- `bash` / `sh` / `shell`：无命令参数，或命令语义非高危（T-0510 判定）→ 放行；
- `写文件`：目标不存在（本次是新增而非覆盖）→ 放行；
- 其余不可逆工具没有可复核的动态结论 → 按静态档走确认（保守）。

### 6.6 拒绝码与观测

被门控拦下时 `状态 = permission_denied`，错误码二选一：
`REVERSIBILITY_CONFIRM`（确认档未通过）与 `GUARD_PRECHECK_FAILED`（前置校验未通过）。
两者都挂 `traceId` / `父traceId` / `建议`，与执行管线其余拒绝路径同形。
`门控日志`（环形，上限 64）记录降档 / 提示 / 校验通过 / 拒绝四类事件，便于复核「这次为什么放行」。

## 7. 复核

```bash
python -m pytest -q tests/test_T0508_可逆性分级.py
python -m pytest -q tests/test_T0448_工具面装配.py
```

当前基线（真实注册表 168 工具，含 T-0508 合入时补的 8 个团队/交付/会话工具）：
`read_only 75 / reversible 40 / semi 5 / irreversible 48`，
`未分级 0`。新增工具不落表 → `未分级` 立刻 > 0，判据红，属于设计意图而不是误报。

平台注意：Windows 上 `head`/`grep`/`awk` 与 `!`/`$()` 不可用，POSIX 判据会 `exit 255` 假失败；
判据本身只跑 `python -m pytest`，不需要 shell 语法。真跑不动时换 `192.168.0.88`（FreeBSD 15.1）。
