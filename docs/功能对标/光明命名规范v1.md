# lightharness 光明命名规范 v1（避坑版）

> 背景：光明编译器按关键字边界拆分中文标识符（缺陷 L-004），保护词表极小。
> 本文档是 lightharness 内可落地的命名约束，帮助在缺陷修复前稳定编码。
> 详见 `docs/功能对标/语言缺陷账.md` L-004。

## 核心原则

**成员名（方法/属性）绝不以其关键字或运算符词根开头/包含。**

## 安全前缀（已验证可作方法名前缀）

`记录`、`汇集`、`整理`、`分析`、`计算`、`汇总`、`判定`、`构造`、`造`、`读`、`写`

## 危险词根（禁止出现在成员名中）

| 词根 | 原因 | 后果示例 |
|------|------|----------|
| `取` | 关键字（取余） | `取全部` → 拆成 `取` + `…` |
| `生成` | 关键字 | `生成模型消息` → 拆成 `生成` + `…` |
| `导出` / `导入` | 关键字 | `导出事件表` → 拆成 `导出` + `…` |
| `新建` | 关键字 | `新建会话`（模块函数可用，但类成员名禁） |
| `模型` | `模`=取模运算符 `%` | `整理模型消息` 生成 `整理 % 型消息()` |
| `事件` | 与 `己.记录X` 调用共存时触发解析器状态 bug | `设 己.事件表 为 []` → `self.事件.表` |
| `类型` | 类型别名语法关键字 | `设 类型 为 ""` 报「期望 =、: 或 为 在类型别名定义中」 |
| `部分` / `原因` | 赋值目标中被拆 | `设 己.部分表 为 {}` → `self.部分.表`；`设 己.原因值 为 空` → `self.原因.值` |
| `用量` 等属性与方法名前缀重叠 | L-007：属性前缀=方法名 → 拆 | `属性 用量值` + `段落 用量` 共存 → `己.用量值 为 X` → `self.用量.值 = X` |
| `打印`、`抛出`、`接口`、`接收`、`属性`、`异步`、`包含`、`匹配`、`排序`、`回调`、`映射`、`枚举`、`返回` | 关键字 | 一律拆 |

## 铁律（新增，L-007 教训）

1. **属性名与任何方法名不得有前缀重叠**（如 `用量` vs `用量值` 必炸）。
2. **类体内局部变量名/方法名/属性名尽量互不同源**；新增任一标识符都可能改变其他成员名的拆分结果（有状态！）。
3. **成员赋值一律写 `设 己.X 为 …`**（裸 `己.X 为 …` 会被编译成 `==`）。
4. **成员下标赋值 `设 己.X[k] 为 …` 若出错**：先 `设 临时 为 己.X` 再 `临时[k] 为 …`；若 temp 名与成员不同名反而破坏构造，可让 temp 与成员同名（生成无害自赋值）。
5. 新增/改名成员后，**必须重新编译并核对生成代码**（见 工具集/校验编译.py 思路），不可凭直觉。

## 易错模式

1. **类体内薄封装方法**：`记录消息事件 接收 …: 返回 己.记录事件(…)` 这种「方法名含被调方法名子串」的写法会触发解析器状态污染，导致其他成员赋值错乱。→ 薄封装方法名不要与 `己.XXX` 被调方法有子串重叠。
2. **成员空列表赋值**：`设 己.事件表 为 []` 在复杂类体下可能被编译成比较。若遇此，先排查类体内是否有危险词根方法/局部变量，改名后再试；仍不行则拆类（把空列表属性放到最小类）。
3. **模块级函数名相对宽松**（`新建会话`、`投影消息`、`是否表面事件` 已验证可用），但类成员名从严。

## 约定

- 遇到未测过的新成员名，先写最小类测试再使用（`examples/test_前缀.light` 思路）。
- 本规范随编译器缺陷修复（L-004 关闭）而松绑；松绑后回填本文件状态。

## 已用安全命名一览（src/会话.light）

- 属性：`标识`、`工作目录`、`父会话`、`种子长度`、`事件表`、`下一序号`、`头部`
- 方法：`记录事件`、`整理消息`、`汇集全部事件`、`事件数`、`压缩替换`、`记录工具结果`、`记录轮次开始`、`记录轮次结束`、`记录请求头`
- 模块函数：`新建会话`、`投影消息`、`是否表面事件`
- ⚠ 已删：`记录消息事件`（触发 L-004 状态 bug，调用方改用 `记录事件`）
- ⚠ 改名：`生成模型消息`→`整理消息`（`模型`=取模）、`导出消息/导出事件表`→`整理消息/汇集全部事件`（`导出`=关键字）、`取模型消息/取全部事件`→同上（`取`=关键字）
