### 3.3 E3 首轮唯一红 → 平台差异定性（E 路实测修正）

首轮 2 failed 同源，唯一红 example 是 `test_会话冷读_接线.light`。B 路首轮曾把它定性为 **"目录列举顺序（FreeBSD readdir 不确定）"** 并登记 E-09。**E 路实机取证推翻该假设**，找到真根因：

| 证据 | 结果 |
|---|---|
| 0.82 单文件直跑 3/3 | **全 rc=1**，失败点在 1b/1c 间漂移（表象） |
| 0.82 单文件再跑 5/5（隔离探针） | **全 rc=1**，稳定红（非 flaky） |
| `文件存在("tmp_probe4/--proj--/sess-a/session.jsonl")`（正斜杠） | **True** |
| `文件存在(日志路径("tmp_probe4","proj","sess-a"))`（持久化.light 生成） | **False** |
| `接线冷读会话文件("tmp_probe4/--proj--/sess-a/session.jsonl")`（正斜杠直读） | 事件数=**2** 正常 |
| 报错信息 | `会话日志不存在: tmp_probe4\--proj--\sess-a\session.jsonl`（**反斜杠**） |
| 本机 Windows 直跑 | **rc=0**（`--- 第6轮 任务E #277 会话冷读接线 测试通过 ---`） |

**真根因**：`src/持久化.light:87` 硬编码
```
段落 会话目录(根, 工作目录, 标识):
  返回 根 + "\\" + 项目键(工作目录) + "\\" + 编码段(标识)
段落 日志路径(根, 工作目录, 标识):
  返回 会话目录(根, 工作目录, 标识) + "\\session.jsonl"
```
Windows 反斜杠。**FreeBSD 上反斜杠是合法文件名字符而非路径分隔符**，故拼出的路径在该文件系统上**不存在** → `冷读会话日志` 走「会话日志不存在」上抛 → `冷读列出会话` 捕获异常记 事件数=-1/状态=读失败。

**为什么初版误判为 readdir 顺序**：example 里 `冷读列出会话(根)` 枚举出的清单里，两条会话**事件数都是 -1**（都读失败）；`清单[0]["会话"]` 恰好仍是 `sess-a`（枚举顺序本身未变），所以先触发的是 **1c（事件数=-1 ≠ 1）**；有时先触发 **1b**（视断言次序/枚举次序微差）。**这是同一反斜杠根因下的表象漂移**，与 readdir 顺序无关。

> ⚠️ **【收口勘误】**：耐久修复后实证，readdir 顺序对 **1b** 确为独立根因（见 §3.5）。反斜杠修复后 1c 消失、两条会话都能读到，1b（会话名顺序）才暴露——故 1b/1c 分属「列举顺序」与「路径分隔符」两个正交维度，原「与 readdir 顺序无关」对 1b 不成立。

**处置**：维持 E-09 登记（平台差异，FreeBSD 上 `pytest.xfail()`），但**把台账 E-09 的"类别"和"根因"改写**为"路径分隔符（Windows 特化反斜杠）"，同步修正 B 路报告 §6.2 与 `docs/多平台差异清单.md` R128 增量 §2。**耐久修复建议**：`src/持久化.light` 改用平台无关分隔符（正斜杠或路径连接）；修复后 E-09 复核销账。

### 3.5 耐久修复与 E-09 销账（最终基线，2026-10-09）

B 路首轮登记 E-09 后，按用户指示「修复后 E-09 销账」做了**耐久修复**，实证后发现 §3.3 的「与 readdir 顺序无关」对 **1b** 不成立——存在**两个正交根因**：

| 症状 | 真根因 | 修复落点 |
|---|---|---|
| 1c 事件数=-1 | `src/持久化.light` 硬编码 Windows 反斜杠作分隔符（FreeBSD 上反斜杠是合法文件名字符）→ 路径拼错 | `会话目录`/`日志路径` 改 POSIX 正斜杠 `/`（光明路径语义本即 POSIX） |
| 1b 会话名顺序 | `冷读列出会话` 透传 `文件列表` readdir 序，FreeBSD/zfs 不保证 `sess-a` 先于 `sess-b` | 两层 `文件列表` 改包 `排序列表(...)` 字典序确定排序 |

0.82 实证（`运行.py examples/test_会话冷读_接线.light` 在 lightharness cwd 与 harness 隔离临时 cwd 两种环境均 rc=0「测试通过」）。

**E-09 销账**：从 `tests/ci_environment_reds.txt` 移除数据行（留可追溯注释）；该 example 不在 `EXPECT_RED`，转为普通绿用例。环境红台账现 **3 条**（E-01/E-02/E-06）。

**最终基线**：`reports/R128_LH_0.82基线_20261009-100618.json`（round=R128-B-E09fix2）→ **2087 用例 / 2066 passed / 0 failed / 18 skipped / 3 xfailed / 866.566s**，pytest_rc=0。较 E-09 登记 re-run（081643.json：2065 passed / 4 xfailed）：passed +1、xfailed 4→3（本例由 xfail 转绿）。

> ⚠️ **本订正取代** §3.3 末句「与 readdir 顺序无关」、§4 FreeBSD 行旧数、§5「E-09 仍维持豁免」框架、§6 E3 旧数（2065/4xfail）、§7 遗留 2「未修」。**E 路原叙事（反斜杠为真根因）对 1c 成立、对 1b 不成立**，耐久修复补齐了 1b 的 readdir 根因。
