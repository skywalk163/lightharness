### 1.2 关键设计：addopts 是否置空 = 按所选解释器**实测**决定（不写死）

`probe_caps()` 在远端实测 `import xdist` / `import pytest_timeout` / `command -v timeout` / `sysctl -n hw.ncpu`，再由 `build_pytest_argv()` 组装：

| 能力 | 处理 |
|---|---|
| 有 xdist | 保留被测仓自带 addopts，显式补 `-n <jobs> --dist loadscope`（jobs 再与 ncpu 取 min） |
| 无 xdist | **`-o addopts=` + `-p no:xdist`**（否则 `-n/--timeout` 找不到插件直接 ARGERROR） |
| 有 pytest-timeout | 追加 `--timeout <case>` |
| 无 pytest-timeout | 不传 `--timeout`，只靠 FreeBSD `timeout(1)` 兜整轮硬超时 |

本次所选解释器 `/tmp/r128-venv/bin/python`（3.12.14）实测：xdist ✅ / pytest-timeout ✅ / `timeout(1)` ✅ / ncpu=8 ⇒ 走「保留 addopts + 显式补 `-n`」分支。

### 1.3 本轮踩到的 5 个坑（已修，别踩回去）

1. **`tests/unit/test_support.py` 是共享基建模块，不是用例文件** —— `--select tests/unit/test_support.py` 收集到 **0 用例**（`no tests collected in 0.06s`，远端 rc=5）。冒烟要挑真用例文件（本轮改用 `tests/unit/test_smoke_support.py`，3 用例）。脚本现已加保护：junitxml 里 `total==0` 直接 rc=3 并报「收集阶段就没跑起来」。
2. **后台模式退出码不可靠** —— `nohup sh -c '<cmd>; echo R128_EXIT=$? >> log' > log 2>&1 &` 实测 `R128_EXIT=` 标记行**偶发不落盘**，`poll_remote` 拿回 `unknown`。⇒ 改**默认前台**执行（`run_remote` + SSH keepalive 30s，不怕空闲被掐），退出码从 `R128_EXIT=` 行取，取不到就用通道 rc；后台模式降级为 `--bg` 可选。
3. **`cleanup` 的 glob 会误伤复用件** —— `/tmp/r128-*` 同时匹配到 `r128-venv`、`r128-shim`（长期复用，删了要重建 venv / shim 也会丢）。⇒ 只认同步树正则 `^/tmp/r128-\d{8}-\d{6}$`，并加 `--yes` 安全阀（不加只列清单）。
4. **`run --` 不引号包裹参数** —— `python -c "import a; print(b)"` 这种含空格的载荷被远端 sh 拆成多词 → rc=2。⇒ 改为逐参数 `_q()` 加引号（代价：该通道不再解释管道/重定向元字符）。
5. **Git-Bash 中文文件名 + 打包** —— 沿用 `git -c core.quotePath=false ls-files`（否则中文路径被八进制转义 → `p.exists()` 恒 False → 静默漏文件）。⚠️ 打包口径 = **tracked 树**（未跟踪文件**不进包**，远端门前该 commit 的先 commit）。

### 3.1 已实测确认（本轮）

| # | 项 | Windows（本机） | FreeBSD 0.82 | 处置 |

### 3.2 沿用既有台账（R81 建立 / R87-M、R88-B 复核，非本轮新增）

`tests/ci_environment_reds.txt` 三条 **FreeBSD 固有环境红**（`tests/test_回归.py` 已按 `sys.platform.startswith('freebsd')` 显式 xfail/skip，junitxml 可辨）：

* **E-01** `test_事件循环.light` —— kqueue 同一 fd 读/写就绪**出列顺序与 epoll/select 不同**，测试钉死「先读后写」⇒ FreeBSD 先报写就绪。
* **E-02** `test_套接字.light` —— 回环 TCP 2.0s 预算内发 200KB，FreeBSD 回环窗口/排空节奏更慢 ⇒ `发送全部` 阻塞超时。
* **E-06** `test_进程树接线.light` —— 沙箱「秒数上限」落到 **RLIMIT_CPU（CPU 时间）**，而 `ping` 阻塞等 ICMP 几乎不耗 CPU ⇒ 1s 上限永不触发；Linux/Windows 沙箱是挂钟看门狗。

⚠️ 权威判据仍是 **`new_reds == 0`**（`test_回归.py` 对台账条目不断言，见 MEMORY §3）。
