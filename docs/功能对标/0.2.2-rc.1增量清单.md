## 6. 架构对齐建议（供决策，不急）

1. LiveShare 的「view / bounded-write 两档 + forking/attachment 两个独立开关」是本轮唯一的**架构级新面**，协议层值得先移植（B3），宿主层留空。
2. Forge 把「变更请求」做成了 provider 中立的注册表 + 轮询调度；若后续要接 Gitea，`urls/review` 两文件是干净切入点。
3. apply_patch 的「先全量 preflight 再逐操作提交」是新的写盘纪律（失败不落半成品），值得在移植里保留（B1 已按「不产生半成品文本」实现）。
4. recommendation 一族把「卡片」抽象成共享 proposal 工具 + 状态机；与既有 #328 智能体指令有重叠，移植前先去重。
