# R70 任务A 交付报告：匿名函数与闭包捕获深化（L-173）

> 批次：光明语言专项升级 R70 · 任务A（匿名函数与闭包捕获深化）
> 日期：2026-09-19
> 改动层：解析器（表达式）+ 代码生成（作用域/nonlocal）
> 关联：L-006（闭包写穿）、L-022（匿名闭包字面量）、L-078（命名嵌套段落）、缺陷账新增 **L-173**

---

## 1. 背景与目标

R66~R69 系统级开发中，回调位置只能用「实例属性暂存 + 无参派发方法」绕（无匿名闭包）。
本任务在表达式位置新增任务书要求的冒号风格匿名函数：

```光明
# 单行体（表达式，自动返回）
设 加法 为 函数(a, b): a + b

# 块体（多语句，需显式 返回）
设 自增 为 函数():
  计数 为 计数 + 1
  返回 计数

# 直接内联为回调（跨行块体也支持）
环.延时回调(30, 函数():
  待派发结果 为 "完成"
  环.停止())
```

## 2. 语法设计决策

| 决策点 | 结论 | 理由 |
|--------|------|------|
| `λ` 别名 | **不新增** | 需动词法器字符分类（`λ` 非 ASCII 标识符成分），与 R20~R28 建立的关键字前缀扫描/词尾并入机制交互面大，收益低；`函数():` 已满足简洁性。留待后续按需评估 |
| 单行体 vs 块体边界 | 冒号后**同一行** = 表达式体（自动返回，编成 Python `lambda`）；冒号后**换行缩进** = 块体（需显式 `返回`，编成嵌套 `def`） | 与任务书「单行形式=表达式体，块形式需 `返回`」一致；与命名 `段落` 语义对齐 |
| 块体在调用实参括号内（跨行） | **支持**。括号内 NEWLINE 被 lexer 抑制（无 NEWLINE/INDENT token），由语句通道按语句边界逐条收敛、以 `)` 收尾 | R69 式回调（`延时回调(30, 函数(): …)`）是本任务的核心使用场景，不能要求挪出括号 |
| 递归 | 匿名函数**不能直接递归**（无名字）——预期限制 | 任务书明确；需递归用命名 `段落` |
| 作用域语义 | 与 L-078 命名嵌套段落完全一致：读外层=自动捕获；裸赋值改写外层标量=自动 `nonlocal`（L-006）；改可变容器=直接操作；参数遮蔽合法；`设`=局部遮蔽（不写穿） | 复用既有 nonlocal 分析，零新语义 |
| 与既有匿名变体关系 | `段落 接收 参数: 体`（L-022）、C 风格 `函数(x){…}`、`接收 …：返回 …` 全部保留不变 | 向后兼容硬约束 |

## 3. 改动点

### 3.1 解析器 `light-merge/src/parser_expr.py`

1. **新增 `_parse_anon_function_colon()`**：挂在 `_parse_primary` 的 `函数` 分支最前。
   - 判据保守：必须凑齐 `函数` `(` 参数 `)` `:` 才认；缺任何一项还原 `self.pos` 返回 None，
     与 C 风格探测、`函数 段名(…)` 段落调用、L-060「关键字当标识符」回退互不干扰。
   - 参数：逗号或空格分隔，支持 `*args` / `**kwargs`。
   - 冒号后换行缩进 → 块体（复用 `_parse_body`）。
   - 冒号后同一行 → 形态分派：
     - 语句关键字开头（设/返回/打印/如果/…）或「标识符 为/等于」赋值形态 →
       `_try_parse_inline_statements()` 语句通道（逐语句收敛，遇 `)/,/]`/换行停，
       `ParseError` 整体回滚）；
     - 其余 → `_parse_logical_expr` 单表达式。
       **必须用 `_parse_logical_expr` 而非 `_parse_expr`**：后者会把 `,` 吃成因果链
       操作符，`执行(函数(v): v + 1, 41)` 会错编成 `(v + 1)(41)`（实测踩坑）。
   - 单个纯表达式语句降级为 lambda 单表达式体（自动返回）。
2. **新增 `_try_parse_inline_statements()`**：括号内跨行块体的语句通道
   （括号内没有 NEWLINE/INDENT token，不能走 `_parse_body`）。

### 3.2 代码生成 `light-merge/src/code_generator.py`

`LambdaExpression` 块体分支（`_light_lambda_N` 命名函数路径）对齐命名段落分支：

- `_push_local_scope()`：体内 `设` 不再泄漏进外层函数的局部名集合；
- 推入 `_function_locals_stack` 函数帧（参数绑定阶段 `_binding_params`，参数遮蔽合法）；
- 函数体生成完毕后按 `_pending_nonlocal` 在 def 行后发射 `nonlocal` 声明。

修复了两个既有隐患（同属 L-173 登记）：
- 匿名闭包块体内裸赋值改写外层标量：此前 nonlocal 误挂到**外层函数**的 pending，
  生成的 Python 在外层 def 里出现 `nonlocal` → SyntaxError；
- 体内 `设` 泄漏进外层函数局部名集合（可错误遮蔽后续同名内置）。

## 5. 限制与后续

1. 匿名函数不能直接递归（预期限制）。
2. 调用实参括号内的跨行块体依赖语句边界启发式收敛；含**顶层逗号的多语句块体**
   （如 `f(函数(): 设 X 为 1, 42)`——顶层逗号后还有实参）在语句通道下存在歧义风险，
   建议此类写法把块体提出括号或用单行表达式体。纯表达式体（`函数(x): x * 2`）
   无此限制（`_parse_logical_expr` 在逗号处天然停）。
3. `λ` 别名未实现（决策见 §2）。
