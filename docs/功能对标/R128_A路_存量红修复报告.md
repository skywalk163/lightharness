## 0. 一句话结论

20 条存量红**全部转绿**，根因不是测试写错、也不是 LH 业务代码写错，而是
**lightharness 自包含 stdlib 快照的能力面落后于 LH 代码已经用到的语义**，分两族三个缺口：

| 族 | 缺口 | 修法 | 覆盖红数 |
|---|---|---|---|
| ① 委派断链 | `内置核心列表.副本` / `.浅拷贝` 真身缺失 | 在 `stdlib/内置核心列表.light` 补齐两个纯光明段落 | **18**（13 example + 5 unit） |
| ② 签名漂移 | `创建临时目录()` 0 参 / `查找目录列表(path)` 1 参，被按 3 参 / 1 参+语义调用 | `stdlib/builtins.py` 两个内建补**向后兼容**的更强签名 | **2**（test_快捷键 / test_文件深） |

⛔ 全程**未改任何测试断言**；⛔ **未改 light-merge 语言核心**；⛔ 未 commit/push。

## 1. 根因定位方法（先定位，不是见红就改）

### 1.1 第一族：builtins 委派断链全量扫描

LH 的 `stdlib/builtins.py` 里有大量「薄封装 → 委派纯光明真身」的形态：

```python
def 副本(原):
    import 内置核心列表
    return 内置核心列表.副本(原)      # ← 真身在 stdlib/内置核心列表.light
```

写脚本扫描全部 159 个 def，对每个 `MOD.ATTR(` 委派检查 `stdlib/MOD.light` 里是否存在
`段落 ATTR(`：

```
委派真身已接通: 67 条 ；断链: 11 条
  内建 副本        -> 内置核心列表.副本     [真身缺]
  内建 浅拷贝      -> 内置核心列表.浅拷贝   [真身缺]
  （其余 9 条为 shutil/os/tempfile/hmac 等 Python 标准库误报）
```

最小探针独立复现（`_r128a_probe/p1.light`，修复前）：

```
$ python 运行.py _r128a_probe/p1.light
RC=1
错误: 属性错误
  属性错误：对象缺少该属性或方法（p1:3）
  （Python 原始错误：module '内置核心列表' has no attribute '副本'）
```

**为什么 LH 会缺**：`副本` 是 light-merge R117 轮补进 `stdlib/内置核心列表.light:24` 导出清单的内建，
LH 的 stdlib 是**自包含快照**（`运行.py` 文档头明确「不依赖 light-merge 的 stdlib」），快照未随 LM 演化同步。

对照两边导出清单（同一份脚本扫 90 个同名 `.light`）：

| 模块 | LH 导出 | LM 导出 | 差 |
|---|---|---|---|
| `内置核心列表` | `… 列表包含 排序列表` | `… 列表包含 副本 列表过滤 列表映射` | LM 多 3 个 |

使用面（`python` 全量统计 `src/` + `examples/`）：

```
副本   56 处 / 22 个文件
浅拷贝  1 处 /  1 个文件（test_修复_拷贝.light）
深拷贝 32 处 / 13 个文件   ← Python copy.deepcopy 实现，不受影响
冻结   16 处 /  5 个文件   ← 同上，不受影响
```

⇒ 只需补 `副本` + `浅拷贝` 两个真身即可覆盖。

### 1.2 第二族：内建签名漂移（委派扫描扫不到）

第一族扫描只覆盖「委派到 `.light` 模块」的形态，扫不到**直接调 Python 库**且**签名被 LH 代码升级调用**的情况。
这两条是在隔离复跑后由实际报错暴露的：

```
$ python 运行.py examples/test_文件深.light
RC=1
  类型错误：查找目录列表() takes from 0 to 1 positional arguments but 3 were given
  （src/文件.light:83）  →  返回 查找目录列表(目录, 样式, 递归)

$ python 运行.py examples/test_快捷键.light
RC=1
  类型错误：创建临时目录() takes 0 positional arguments but 1 was given
  （test_快捷键:232）    →  设 临时根 为 创建临时目录("lh_sc_test")
```

先做了一次「LH vs LM builtins.py 同名 def 签名」全量比对：**159 vs 158 个 def，签名漂移 = 0**。
⇒ 说明**两边 builtins 一样旧**，不是 LH 单方面落后，而是 LH 代码已经按更强语义在调用，
能力面（LM 与 LH 双侧）都没跟上。语义依据：

- `创建临时目录(后缀, 前缀, 目录)` —— LM `stdlib/临时文件.light:16` 已导出同名 3 参版本，
  LH 代码按该语义调用，但**内建优先**抢到了 0 参版本。
- `查找目录列表(目录, 样式, 递归)` —— `src/文件.light` 的 `查找文件(目录, 样式, 递归)` 需要
  glob 样式匹配 + 递归开关；测试 `examples/test_文件深.light:127-132` 明确断言：
  `查找文件(glob目录, "*.txt", 假)` → 长度 == 2；`查找文件(glob目录, "*.json", 真)` → 长度 >= 2。

## 2. 修法（两处，均向后兼容）

### 2.1 `stdlib/内置核心列表.light` —— 补 `副本` / `浅拷贝` 真身

从 LM `stdlib/内置核心列表.light:69/82` 移植（纯光明实现，只依赖已验证可用的
`isinstance` / `字典键列表` / 字典下标赋值，见 §3 前置验证）：

```光明
段落 副本(原):
  如果 isinstance(原, dict):
    设 复 为 {}
    遍历 键 之 字典键列表(原):
      复[键] 为 原[键]
    返回 复
  如果 isinstance(原, list):
    设 复 为 []
    遍历 元素 之 原:
      复.追加(元素)
    返回 复
  返回 原

段落 浅拷贝(原):   # 与 副本 同语义（L-083 一等原语）
  …
```

同时把 `副本` 加进导出清单（对齐 LM 第 24 行）：
`导出 列 列表创建 … 列表包含 排序列表 副本。`

> 写盘：bytes 读写，落盘后核验 **CRLF=91 / bareLF=0**（与文件原先行尾一致，符合项目铁律）。

### 2.2 `stdlib/builtins.py` —— 两个内建补向后兼容签名

```python
def 创建临时目录(后缀=None, 前缀=None, 目录=None) -> str:
    # 全默认 → 行为与旧 0 参完全一致
    return tempfile.mkdtemp(suffix=后缀 or '', prefix=前缀 or '', dir=目录)

def 查找目录列表(路径: str = '.', 样式=None, 递归=False) -> list:
    if 样式 is None:
        return os.listdir(路径)          # 旧 1 参行为完全不变
    # 样式非空 → fnmatch 匹配，返回完整路径；递归=真 走 os.walk，假 只看顶层文件
```

**向后兼容性**：两处新参数全带默认值，旧调用点（0 参 / 1 参）行为逐字不变 ⇒ 无回归面。
