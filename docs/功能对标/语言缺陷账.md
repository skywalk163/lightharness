# 光明语言缺陷账（lightharness 复刻中发现）

> 本账记录 lightharness 复刻过程中暴露的「光明写不出 / 写错 / 绕不过」的语言缺陷。
> 每条：编号 + 现象 + 最小复现 + 期望能力 + 状态（新发现/已登记/已修复）。
> 汇总后移交光明开发团队（A9 泳道）。

| 编号 | 现象 | 最小复现 | 期望能力 | 状态 |
|------|------|----------|----------|------|
| L-001 | **跨目录点号模块导入不可用**。`从 子目录.模块 导入 符号` 编译期不内联（`_resolve_local_imports` 只认同目录模块），运行期 `No module named '子目录.模块'`（即使子目录有 `__init__.py` 也不解析）。 | `lightharness/examples/_import_test/入口2.light`（同目录导入 `入口3.light` 正常，点号导入必失败） | 支持分层目录组织（原版 harness 是 50 个分层 package；光明需要 `包/子模块` 点号导入） | **新发现** |
| L-002 | **不支持多行表达式/字面量续行**。字典/列表字面量跨行（逗号后换行）直接语法错误「意外的标记: 换行」；复杂数据结构只能压成单行，可读性极差。 | `消息.light` 原稿第 46 行：`返回 ["id": 造标识(), "role": "assistant", "content": 内容,` 换行即报错（已改单行绕过） | 支持括号内换行续行（Python 风格）或行尾逗号续行 | **新发现** |
| L-003 | **类内成员空列表赋值被误编译成比较/拆分**。类体内出现 `己.X.追加(...)` 调用或名为「追加」的方法时，构造段 `己.X 为 []` 被编译成 `(self.X == [])`（比较）或 `self.事件.表 = []`（拆分），X 保持 None。 | `examples/test_追加方法2.light`、`test_局部事件.light`（含 `设 事件 为 ...` 局部变量 + `设 己.事件表 为 []`）必炸 | 成员空列表赋值必须稳定编译为赋值；局部变量名不得污染后续标识符解析 | **新发现** |
| L-004 | **词法器按关键字边界拆分中文标识符（严重，家族性）**。保护词表仅 16 个（函数/包含/匹配/回调/打印/排序/接口/枚举/标准库/模块/段落/结构体/联合体/输出/返回/配），凡未受保护的复合词：① 以关键字开头的成员名被拆（`导出事件表`→`导出`+`事件表`、`取全部事件`→`取`+`…`、`生成模型消息`→`生成`+`…`）；② 含运算符词根被改写（`模型消息` 中 `模`=取模 `%`，`整理模型消息()` 生成 `整理 % 型消息()`）；③ 与特定成员调用共存时整段成员赋值错乱。 | ① `导出` 开头方法：`'会话' object has no attribute '导出'`；② `整理模型消息` 生成 `(会话对象.整理 % 型消息())`；③ `记录消息事件`+`己.记录事件` 共存时 `设 己.事件表 为 []` 错乱 | 中文无空格，需可靠的复合词切词机制：完整标识符最长匹配优先、保护词表自动化扩充或改为「标识符不做内部拆分」 | **新发现（最高优先级）** |
| L-007 | **成员名拆分有状态性（L-004 家族，最不可预测的表现）**。① 属性名与方法名前缀重叠会被拆：属性 `用量值` + 方法 `用量` 共存 → `己.用量值 为 X` 编译成 `self.用量.值 = X`；② 词根 `部分/原因/类型/用量` 在「设 己.X 为 …」赋值目标中会被拆（`设 己.部分表 为 {}`→`self.部分.表={}`、`设 己.原因值 为 空`→`self.原因.值=None`）；③ **类体内新增/改名一个局部变量，会改变其他成员名的拆分结果**——把 `确保` 方法里 temp `残块表` 改成 `残块字典`，构造函数 `设 己.残块表 为 {}` 立即从正确 `self.残块表={}` 错乱成 `self.残块.表={}`。 | 见 `examples/_流生成.py`（多次改名前后对比）；`src/流.light` 最终绕法：temp 与成员同名使生成无害自赋值 | 拆分决策必须与模块/类符号表状态无关（确定性、可复现）；同一源码同一次编译结果应稳定 | **新发现（最高优先级）** |
| L-005 | **非 self 的成员下标访问被编译成调用**。`总线.监听器表[事件名]`（`变量.成员[下标]` 且非 `己.成员[下标]`）被编译成 `总线.监听器表([事件名])`（把 `[下标]` 当参数列表），运行期 `'dict' object is not callable`。`己.成员[下标]` 与 `局部变量[下标]` 均正常，仅「非 self 成员 + 下标」组合炸。 | `事件.light` 造取消处理器原稿：`设 表 为 总线.监听器表[事件名]` → 生成 `表 = 总线.监听器表([事件名])` | 成员访问与下标访问组合必须稳定编译为下标 | **新发现** |
| L-006 | **闭包内不能修改外层局部标量**。内层 `段落` 对 `设` 于外层同名标量做 `X = X + 1` 式更新，生成 Python 后 `X` 成为内层局部，运行期 `UnboundLocalError: cannot access local variable 'X'`。 | `test_事件.light` 初稿：外层 `设 计数 为 0`，内层处理器 `计数 = 计数 + 1` 必炸 | 内层函数对闭包捕获变量赋值应生成 `nonlocal X` 或提示改用可变容器 | **新发现** |
| L-007b | **模块级局部变量名污染跨模块成员访问（L-007 跨模块形态）**。`a.light` 的模块函数里若有局部变量名 `头`/`事件`/`轮次`，则对 `b.light` 对象的成员访问 `对象.头信息`/`对象.记录事件` 会在本模块被拆成 `对象.头`+`…`/`对象.记录(事件…)`（成员名与局部变量名共享词法边界决策）。`头部` 属性在 `会话.light` 内部 `己.头部` 正常，但在 `持久化.light` 里 `会话对象.头部` 即被拆 → 已改名 `头信息`；`记录事件` 在 `代理.light` 正常、在 `持久化.light` 因局部 `事件` 被拆 → 新增安全方法 `补录`。 | `持久化.light` 原稿：局部 `设 头 为 会话对象.头部` → `'会话' object has no attribute '头'`；局部 `事件` 使 `会话对象.记录事件(...)` → `会话对象.记录(事件(...))` | 成员名解析应只由「对象自身的类定义」决定，与调用方模块的局部变量无关（确定性） | **新发现** |
| L-007c | **类内局部变量名与属性名前缀重叠触发属性拆分**。`代理.light` 属性 `轮次计数`/`步骤计数`，因 `执行步骤(轮次, 步骤)` 方法参数 `轮次`/`步骤` 存在，`设 己.轮次计数 为 0` 编译成 `self.轮次.计数 = 0`（`计数` 中 `数` 也是关键字）→ 改名 `轮号`/`步号`。 | `代理.light` 初稿：`设 己.轮次计数 为 0` → 生成 `self.轮次.计数 = 0` | 属性名解析不应受方法参数名影响；`数`/`值`/`次` 等常用字被关键字化导致命名大面积受限 | **新发现** |
| L-008 | **模块级 JSON 序列化函数并非全局内置**。`序列化`/`解析JSON` 不是模块级自动可用符号；`序列化` 须 `从 JSON 导入 序列化JSON`（函数名是 `序列化JSON` 而非 `序列化`），直接调用 `序列化(...)` 运行期 `name '序列化' is not defined`。`解析JSON` 在多数模块可用（编译器内置注入）但同属 JSON 模块。 | `持久化.light` 初稿：`设 文本 为 序列化(行对象(...))` → `name '序列化' is not defined`（改 `从 JSON 导入 序列化JSON` 后通过） | 文档化 JSON 序列化入口：全局 `序列化` 或统一 `从 JSON 导入`；避免同名不同函数（`序列化` vs `序列化JSON`） | **新发现** |
| L-009 | **注释内嵌 `导入 X` 字样会被 `-replace` 类文本替换误伤（工程层陷阱）**。脚本批量改名时，若替换串 `导入 builtins` 同时命中注释 `# …用「导入 builtins…`，会在注释行中插入换行，把注释尾巴变成代码行，报「无法识别的语法元素：'（'」这类伪语法错误，误导排查。 | `持久化.light` 曾用 PowerShell `-replace '导入 builtins', "导入 builtins\n从 JSON…"` → 注释 `# …用「导入 builtins` 被劈开，`从 JSON 导入 …」取 Python 内置…` 变成代码行 | 注释应被词法忽略；文本级批量替换工具应避免命中注释/字符串内的目标串 | **新发现** |
|  | | | | |

## 提交规则

1. 每条缺陷必须在对应模块的功能对标卡里登记，并在此汇总。
2. 最小复现必须能在 lightharness 里独立运行，便于开发团队复现。
3. 绕法（如果有）一并记录，避免团队重复踩坑。

## lightharness 当前绕法（L-001）

光明复刻采用**扁平目录 + 命名前缀**：所有 `.light` 模块平铺在 `src/`，模块名用「会话」「消息」等短名区分；
原版分层 package 结构（`core/session`、`llm/llm` 等）在光明侧以「模块名直接对应功能」的方式映射，
映射关系记录在 `docs/架构设计.md` §8 模块清单。
