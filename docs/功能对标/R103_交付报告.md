## 2. 与任务书题面口径的两处差异（如实记录）

1. **#249「minimal 7 行」与「可挂载上限 6」不是一回事。**
   #249 的组合统计口径含「组行自身 + `preset-*` 声明行」→ minimal 插件行 7 / 展平后 8；
   #250 的扁平 id 集由 `预设深化.展平行` 产出，**不产出组行自身** → minimal 实际是 **6**
   （persona / pty / terminal-bash / persistent-bash / terminal-pwsh / persistent-pwsh）。
   四预设实测扁平 id 数：**minimal 6、standard 29、ptc 30、cordis 30**。
   即挂载层能挂载的上限是 6，而非题面按 7/8 推算的值。属口径差，非缺陷。
2. **不存在「linux 全挂载」。**
   上游 `minimal.patch.yml` 的 bash 系与 pwsh 系是**对称**的：
   `terminal-bash` / `persistent-bash` 的 disabled 是 `process.platform === 'win32'`，
   `terminal-pwsh` / `persistent-pwsh` 的是 `process.platform !== 'win32'`。
   故实测为：win32 求值能力下禁用跳过 **2**（bash 系），linux 求值能力下禁用跳过 **2**（pwsh 系）。
   题面「linux 全挂载」的口径与上游数据不符，按上游实测口径落地。
