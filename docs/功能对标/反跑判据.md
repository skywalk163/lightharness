## 1. 判红 / 判绿总则

- **判红（缺陷未修）**：`python 运行.py examples/test_L0XX.light` 退出码 ≠ 0，且错误信息与文件头「# 当前：」行描述一致。

- **判绿（缺陷已修）**：启用「修复后断言」段（见 §2），退出码 = 0，且 `断言修复后()` 内全部 `断言等于` 通过。

- **反跑即判据**：用例本身同时是复现脚本与验收脚本；未修保持红，修好后启用断言转绿。

## 2. 「修复后断言」段写法与启用方式

每个用例文件统一结构：

```
# 缺陷：L-0XX <一句话现象>
# 当前：<预期红/报错现象>
# 修复后：<应绿的行为断言>
（复现段：触发缺陷的最小源码）

# 修复后断言段——当前刻意不调用（修复后启用）
段落 断言修复后:
  断言等于(<实际>, <期望>, "L-0XX …")

段落 断言等于 接收 实际, 期望, 标签:
  如果 实际 != 期望:
    抛出 "断言失败: " + 标签 + " 实际=" + 转字符串(实际) + " 期望=" + 转字符串(期望)

段落 主:
  <复现段>
  打印 "--- 测试L0XX 结束 ---"
  # 修复后启用：断言修复后()

主()
```

**启用步骤（语言团队修复缺陷后）**：把 `主()` 里 `# 修复后启用：断言修复后()` 的注释去掉，使 `断言修复后()` 被调用；用例即从「红」转为「绿」。

**断言失败语义**：`断言等于` 不匹配即 `抛出`，运行器按运行期异常分类、退出码非 0 → CI 判定为失败（防「假绿」）。

2. **验收**：落在对应模块功能对标卡（`对标清单.json`）的「语言缺陷」+「反跑判据」字段，判据即该模块的测试用例——把判据测试里的行为改反（抛↔不抛、值改错、分支取反）必须立红，否则不算判据成立。
3. **典型例子**：L-050（捕获变量单字 `e`）、L-053（`己` 为 self 保留名）、L-054（嵌套字面量实参内 `\n` 破坏缩进）均由 `test_语言服务器.light` 等模块测试锁定，可在对应对标卡追溯到复现与绕法。

## 4. L-009（工程层）判据

L-009 是文本级批量替换缺陷，不是语言运行时缺陷，直接运行 `test_L009.light` 恒绿。判据：

**陷阱复现（仅作反面教材，禁止在 CI / 日常开发使用）**——裸 `-replace` 不感知词法，会把含「导入 builtins」字样的注释行劈开：

```
# 对副本执行（含「导入 builtins」字样的注释行会被劈开）：
$c = Get-Content examples/test_L009.light -Raw -Encoding UTF8
$c -replace '导入 builtins', "导入 builtins`n从 JSON 导入 序列化JSON" > 副本.light
python 运行.py 副本.light   # 红（伪词法错误：注释尾巴变成代码行）
```

**正确做法（已落地）**：使用工程层词法感知替换工具 `scripts/安全替换.py`，它跳过注释与字符串字面量、仅替换真实代码区域并保留缩进；裸 `-replace` 触碰 `.light` 源码已在 `docs/CI.md` 明确禁用。

```
# 安全替换：注释/字符串内目标串跳过，真实代码行正常替换并保留缩进
python scripts/安全替换.py examples/test_L009.light "导入 builtins" "导入 builtins`n从 JSON 导入 序列化JSON" --out 副本.light
python 运行.py 副本.light   # 绿（注释未被劈开）
python scripts/安全替换.py --self-test   # 内置自测：注释/字符串跳过、代码行替换
```
