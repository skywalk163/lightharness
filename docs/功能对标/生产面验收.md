# 生产面验收（T-0488）

本文件配套 `tests/test_T0488_生产面快照.py`：前者是**可重复的自动化判据**，后者是**真实 web 会话的手工验收清单**。
自动化判据不调模型、不联网、不读家目录；手工清单必须走真实模型与真实 `request/header`。

## 0. 一句话结论

自动化判据钉住的「生产装配函数」当前产出：**22 个工具 / 8,600 字符 schema / 3,150 字符带上下文提示 / 3,260 字符装配快照**（含两级 AGENTS.md）。
真实 web 会话是否也是这个数字，**只能靠下面第 3 节的手工清单回答**——这正是 T-0448/T-0456「单测绿、真实请求面仍是 4 个工具」的教训。

## 1. 自动化快照（2026-11-25，Windows / Python 3.13）

| 项 | 实测 | 判据 |
|---|---|---|
| `组装注册表("standard")` 工具数 | **22** | 20–30 |
| 描述表条数（模型可见） | **22**（与注册表逐件一致） | `== 工具数` |
| 描述表 JSON 字符数 | **8,600** | 5,000–15,000 |
| 带上下文提示长度 | **3,150** | 3,000–6,000，无截断标记 |
| 同上·无上下文（当前生产调用方口径） | **2,563** | 仅记录，见第 2 节缺口 |
| 默认系统提示（两级 AGENTS） | **2,673** | 两级都在、契约之前、各一次 |
| 生产装配快照（指令段 + 带上下文契约） | **3,260** | 3,000–6,000，契约收尾 |
| 提示硬上限 | **6,000** | `生产提示上限()` |
| 压缩检查点 | 8 个 `##` 标题、`<compacted-summary>` 包裹、`摘要来源=model` | 全中 |

口径偏差（与任务卡）：卡面写「带上下文提示 4500–6000」。T-0477 白名单收口后，全上下文原文实测 3,150 字（旧原文 2,563 + 六段约 587），**4,500 这个下界无论怎么接线都到不了**；与 T-0487 同一口径改钉「≥ 3,000 且 ≤ 6,000 且无截断」。真正要守的是「六段全进 + 不超预算 + 契约收尾」，不是写大了的下界。

## 2. 生产面现状缺口（先看，再验收）

`总入口.跑一轮` 的 `本轮系统提示` 走 `默认系统提示文本(项目根, 工作目录)` → `通用工具契约文本()` → `生产提示文本(工具名表)`，**没有传 `上下文`**。
因此真实请求里的系统提示是**无上下文那一版**：实测 2,563 字，缺少环境段、技能段、MCP 段（`操作系统：` / `当前本地时间` / `以下技能可用` / `MCP resource servers` 四条都不在）。

这意味着：

- 本卡的自动化判据钉住的是「装配函数带上下文时的能力」（T-0487 已把六段接进 `生产提示文本` 的 `上下文` 形参）；
- **生产调用方还没把上下文传进去**——这是本轮快照暴露的缺口，不是本卡判据红。合入后若手工清单实测仍是 2,563 字、没有 `操作系统：`，按缺陷记入台账，不要当成「通过」。
- `GET /api/sessions/current` **不返回** `系统提示` / `工具数`（见 `src/web服务器.light:2243 处理当前会话`，只回会话元数据）。真实请求面的唯一证据是会话 JSONL 里的 `request/header` 事件（`数据.系统提示` + `数据.工具模式`），下面用它验收。

## 3. 手工验收清单（只写命令与观察点）

> 全程只读仓库与自己的会话目录；不要改 `src/*.light`。所有路径里的 `<user>` 是占位，不要写进交付文档。

### 3.1 起服务（固定端口）

前提：`.env` 或环境变量里已有可用的大模型 Key（`DEEPSEEK_API_KEY` / `HARNESS_API_KEY` / `OPENAI_API_KEY` 任一）。没有 Key 就先跑自动化判据，手工清单等有 Key 再补。

```powershell
$env:HARNESS_WEB_NO_OPEN='1'
$env:HARNESS_WEB_PORT='7788'
$env:HARNESS_WEB_MOCK='0'
python 运行.py examples/运行Web服务器.light
```

观察点：

- [ ] 启动日志出现 `7788`（若出现 `端口回退`，记录回退原因，改用日志里的实际端口）；
- [ ] 日志/URL 里有 `?token=...`；把它记到临时变量，后续请求带上。

### 3.2 新建会话并跑两轮真实任务

浏览器打开 `http://127.0.0.1:7788/?token=<启动日志里的令牌>`，新建会话，工作目录填 `G:/dswork/duan-light-merge`。

第一轮输入（改一个文件）：

```text
读一下 README.md 里「快速上手（5 分钟）」那一节，把其中一处明显过时的命令改掉，只改这一处，不要重写整文件；改完告诉我改了哪一行。
```

第二轮输入（跑一条测试）：

```text
跑一条最快的测试证明仓库没坏，把命令和结果（通过/失败条数）贴给我。
```

观察点：

- [ ] 两轮都出现**工具卡片**（读文件 / 编辑文件 / bash 之类），不是纯文本自述；
- [ ] 每轮结束有可读的**结束原因**（正常完成 / 步数上限 / 出错），不是空白；
- [ ] 编辑文件只改目标行（`git diff` 只出现这一行；出现第二处即记失败；验收后自行还原，不要提交）。

### 3.3 取真实请求面数字（唯一证据：request/header）

```powershell
$根 = if ($env:HARNESS_HOME) { $env:HARNESS_HOME } else { Join-Path $env:USERPROFILE '.lightharness' }
$f = Get-ChildItem (Join-Path $根 'sessions\*.jsonl') | Sort-Object LastWriteTime | Select-Object -Last 1
python -c "import json,sys; ev=[json.loads(l) for l in open(sys.argv[1],encoding='utf-8') if l.strip()]; h=[e for e in ev if e.get('类型')=='request/header']; d=h[-1]['数据']; p=d['系统提示']; n=[t['function']['name'] for t in d['工具模式']]; print('会话',sys.argv[1]); print('提示长度',len(p)); print('工具数',len(n)); print('工具名',','.join(n)); print('有操作系统行','操作系统：' in p); print('有当前本地时间','当前本地时间' in p); print('有技能段','以下技能可用' in p); print('有MCP段','MCP resource servers' in p); print('契约收尾',p.rstrip().endswith('不要继续重试。'))" $f.FullName
```

判读规则（照实记录，不猜）：

| 观察结果 | 结论 |
|---|---|
| 提示长度 ≥ 3,000、工具数 20–30、工具名含 `edit_file` 与 `todo_write`、四条段标记齐全、契约收尾 True | 生产面与装配函数一致，通过 |
| 提示长度约 2,563 且 `有操作系统行=False` | 命中第 2 节缺口：上下文未传入，记缺陷，不算通过 |
| 工具数 < 20 或工具名缺 `edit_file` / `todo_write` | 请求面被截断，记缺陷（T-0448/T-0456 同类） |

把三项实测数字填进第 4 节。

### 3.4 触发压缩并测「压缩后首帧」

用更小的窗口重启服务（先 `Ctrl+C` 停掉 3.1 的进程）：

```powershell

$env:HARNESS_COMPACTION_THRESHOLD_RATIO='0.5'

```

在同一会话里连续发长文本（每次 ≥ 1,000 字，粘一段日志即可），直到前端出现压缩提示/检查点。

观察点：

- [ ] 出现压缩事件后，检查点消息带 `<compacted-summary>` 边框；
- [ ] 压缩完成后**立刻**发一条 `继续`，用秒表记「发送 → 第一条 assistant 文本出现」的墙钟时间；
- [ ] 该时间 ≤ 30 秒；超过则记缺陷（压缩后首帧卡顿）。

再跑一次 3.3 的命令，记录新 `request/header` 的四条段标记；任一条转 False 即记缺陷（压缩把系统提示挤掉）。
