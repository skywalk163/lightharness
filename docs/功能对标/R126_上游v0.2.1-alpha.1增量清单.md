## 5. schedule reminder 拒绝链单独评估（可否复刻为纯规则）

**结论：可复刻。规则本体纯，宿主接触点均为可投影输入。**

链条五段（按 commit 时序）：

1. **`6c1a590a4c` preset-scoped package**：四工具（schedule_create/list/delete/update）从 `dsh-schedule` 服务包迁到独立 `tool-schedule` 包，由 preset 行（standard/cordis/ptc 声明）挂载而非 agent/created 监听。**架构面**：挂载方式属宿主组合；**逻辑面**：工具 schema（六种 timing 视图 oneOf、错误 schema basicErrorSchema）、`validateCreateArgs`（exactly-one selector）、`invalidInterval` 均纯函数 → §4-1。
2. **`96c421d985` subagent ownership**：`ScheduleService` 新增私有 `reminderTargetRefusal(sessionId)`：`agent = ctx.agents.get(sessionId)`；`agent===undefined || delegationDepthOf(agent)===0 → 放行`；否则返回 `{code:'subagent_session', message:'This Session belongs to subagent routing, …'}`。**规则本体**=「delegation 深度>0 → 拒绝投递不可达 Session」一条；`delegationDepthOf` 来自 `dsh-subagent`（光明侧已有 子代理核心/子代理深化.light 承载 delegation 记账）。create 在 serialize 队列内 throw `ScheduleInputError('subagent_session')`（domain.ts 新增该 code）。
3. **`500295b2bd` update refusal 走 result**：update 对 refusal 改为返回非变更 result（`{code:'subagent_session',…}`），不再 throw——因 Remote 网关把 throw 变 failed result，Web 编辑器只映射 result.code。**结果通道选择规则**：create 无 result 路径故 throw，update 有故返回。
4. **`699f1a8dc1` preset toolFilter.deny**：三个 preset 的 `tool-subagent`/`tool-subagent-fork` 行 deny 四工具名，provider 经 `ctx.tools.restrict()` 在子作用域摘除。**宿主面**（preset 组合+restrict 机制）。
5. **`1b1b09e1fb` 工具层 caller restriction**：四工具 execute 前各自调 `subagentCallerRefusal(exec.agent)`（同一条深度规则，message='A delegated subagent cannot use reminders.'），使 list/delete/content-only update 也拒绝；与 preset deny 互为两层（prompt 层+执行层）。

**光明落点**：`调度深化.light`（或 `定时提醒框架.light`）实现一条 `定时目标拒绝(深度)` 纯规则 + `定时工具拒绝(调用方)` 工具层规则；delegation 深度由子代理模块投影输入；回归用例：①深度>0 create → `subagent_session` 立红；②update 返回 refusal 而非抛错；③list/delete 亦拒绝；④深度=0 放行。
