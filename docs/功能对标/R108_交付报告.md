### 1.3 债务 3 —— `examples/运行Web服务器.light`（归属 B 线，根因最深）

- **门禁症状**：`错误: 导入错误 cannot import name '绝对路径' from '文件系统' (unknown location)`。
- **根因（主 agent 实测定案）**：**cwd 相关，不是缺符号**。`文件系统.light` 是「纯光明实现」门面并**确实导出** `绝对路径`（`stdlib/文件系统.light:12` 导出、`:93` 定义；`文件系统.py:98` 也有）。实测：**cwd=仓库根 → rc=0（正常起服）**；**cwd=系统临时目录（门禁 `_run` 的做法）→ rc=1** 报上述 ImportError。已排除 stdio 因素（`capture_output` 管道与 `inherit` 均复现）。`unknown location` = 模块退化成**空命名空间包** ⇒ cwd 变化时「纯光明实现」门面解析失败。
- **修在哪一层**：**B 线（`stdlib/_light_import_hook.py`，import hook 层）**——这是唯一能在 cwd 变化时稳定解析包内模块的层；改在测试层只能掩盖。
- **修复方式**：`stdlib/_light_import_hook.py` 32 行增量，让「纯光明实现」门面的子模块解析不再依赖 cwd。

**旧行为 → 新行为对照**：

| 维度 | 旧 | 新 |
|---|---|---|
| cwd = 仓库根 | rc=0 | rc=0（不退化） |
| cwd = 临时目录 | rc=1（`unknown location`，门面退化成空命名空间包） | rc=0（门面子模块正常解析） |
| 覆盖范围 | 依赖当前工作目录 | 与 cwd 无关，稳定解析 |

### 1.4 债务 3 根因结论（报告必答项）

> **结论：`运行Web服务器.light` 的红，根因在 import hook 对「纯光明实现」门面子模块的解析 cwd 敏感。** 该门面（`stdlib/文件系统.light`）在 cwd ≠ 仓库根时会退化成空命名空间包，`文件系统` 名字空间里找不到 `绝对路径`，于是 `from 文件系统 import 绝对路径` 报 `cannot import name ... (unknown location)`。
> **修在哪一层：stdlib 的 import hook 层（`stdlib/_light_import_hook.py`）**，不是测试层、也不是 `文件系统.light` 本身（它符号齐全）。这是本轮唯一动到的源码层修改，也是三例债务里唯一真正的实现缺陷。

## 六、线 K：`account`「账号与余额」页的结论性处置（§3.7③）

**结论：不实现，销账。**

上游事实（考据，R108 §1.3）：

- 注册条件硬绑 `snapshot.view?.status === 'credential-stored'`（`ui-settings-account/src/client/index.ts:289-305`），且整插件只在 Desktop 渲染器激活（`index.ts:44`）。
- 该状态**只可能**来自 credential store 里的 grant；grant 只能由 `auth_exchange` 成功写出。**没有账号后端 ⇒ 永远 `signed-out` ⇒ 该页签永不注册。**
- 登录是 **PKCE(S256) 浏览器授权码 + 本地 `/oauth/callback`**（非 device code、非粘贴 token），涉及 Platform HTTP（`/auth-api/v0/dsh/auth_init`、`/auth_exchange`、`/auth_cancel`）与凭据落盘。
- **上游没有「只读状态展示」形态**；未登录空态在上游实践上只是登出瞬间的过渡帧。**上游未定义「无账号后端」模式下该页的既定形态。**
- 另：**该页没有登出按钮**——登出在 `settings.launcher` 的 AccountMenu（`AccountMenu.tsx:71-77`）。

**推论**：本仓无账号/计费后端，硬做该页只能**自造上游不存在的形态**（偏离优先于对齐）。按任务书铁律「不许硬造一个偏离上游的替代形态」，本轮**不实现**。

**销账登记**：R107 §九 该条已更新为「R108 §3.7③ 已销账（结论：不实现）」，附本结论。`settings.launcher` 的「未登录」只读态列为**可选**（若要，另立小项，不在本轮）。
