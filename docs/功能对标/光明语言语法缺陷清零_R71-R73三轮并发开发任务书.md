## 三、R71 第 1 轮：核心语法补缺

### 任务 A：三元表达式（G-01，高优先级）

**目标**：支持 Python 风格三元表达式，消除简单条件赋值的样板代码。

**最小复现（当前报错）**：
```光明
设 结果 为 如果 x > 5: "大" 否则 "小"  # 解析错误：意外的标记「:」
```

**期望语法（两种形式，二选一或都支持）**：
```光明
# 形式1：Python 风格（推荐，与现有 如果/否则 关键字对齐）
设 结果 为 如果 x > 5 则 "大" 否则 "小"

# 形式2：C 风格（简洁，但需引入 ? : 符号）
设 结果 为 x > 5 ? "大" : "小"
```

**实现要点**：
1. `parser_expr.py`：在表达式解析中新增三元表达式分支，优先级低于赋值、高于 `或`/`且`
2. 形式1：前瞻 `如果` + 条件 + `则` + 表达式 + `否则` + 表达式，生成 `cond if_true if cond else if_false`（Python 三元）
3. 形式2：前瞻 `条件 ? 表达式 : 表达式`，生成同上
4. `code_generator.py` / `code_generator_unified.py`：新增 TernaryExpr AST 节点生成
5. 注意：`如果` 在表达式位置需与语句位置的 `如果` 区分（语句位置后跟冒号+块体，表达式位置后跟条件+则）

**测试用例**：`examples/test_R71_A_三元表达式.light`
- 基础三元（数字/字符串/布尔）
- 嵌套三元
- 三元作为函数参数
- 三元与算术运算混合
- 三元条件为假时取否则分支
- 形式1与形式2等价性断言

**验收标准**：
- ✅ 上述语法编译通过，运行结果正确
- ✅ 现有 `如果...否则...` 语句不受影响
- ✅ 全量回归零红

**风险评估**：低。`如果` 关键字在表达式位置的前瞻需谨慎，避免与语句位置冲突。建议形式1优先，形式2可选。

### 任务 B：增量赋值运算符（G-02，高优先级）

**目标**：支持 `+=`/`-=`/`*=`/`/=` 等增量赋值的中文对应语法，消除 `x 为 x + 1` 样板。

**最小复现（当前报错或静默失败）**：
```光明
设 n 为 10
n 加为 5  # 解析错误或静默不执行
```

**期望语法**：
```光明
设 n 为 10
n 加为 5    # n += 5 → n = 15
n 减为 3    # n -= 3 → n = 12
n 乘为 2    # n *= 2 → n = 24
n 除为 4    # n /= 4 → n = 6.0
n 取模为 5  # n %= 5 → n = 1.0
n 幂为 3    # n **= 3 → n = 1.0
```

**实现要点**：
1. `keywords.py`：新增增量赋值关键字 `加为`/`减为`/`乘为`/`除为`/`取模为`/`幂为`（双字关键字，进 KEYWORDS_DOUBLE）
2. `parser_stmt.py`：`_parse_assignment_stmt` 新增增量赋值分支，识别 `标识符 增量关键字 表达式`
3. `code_generator.py`：生成 `x += expr` / `x -= expr` 等 Python 增量赋值
4. 支持成员下标增量：`己.计数 加为 1` → `self.计数 += 1`、`字典["键"] 加为 1` → `字典["键"] += 1`
5. 注意：`加为` 等关键字需进 lexer 的 `_COMPOUND_SAFE_SINGLE_KEYWORDS` 或类似保护，避免 `增加为`/`参加为` 等复合词被切碎

**测试用例**：`examples/test_R71_B_增量赋值.light`
- 基础增量（加/减/乘/除/取模/幂）
- 成员变量增量（`己.x 加为 1`）
- 字典下标增量（`d["k"] 加为 1`）
- 列表下标增量（`lst[0] 加为 1`）
- 增量后值断言
- 与普通赋值 `为` 共存不冲突

**验收标准**：
- ✅ 上述语法编译通过，运行结果正确
- ✅ 现有 `为` 赋值不受影响
- ✅ 全量回归零红

**风险评估**：中。`加为` 等双字关键字可能与现有代码中的标识符冲突（如 `增加为`），需做好复合词保护。建议先全仓扫描 `加为`/`减为` 等词的出现情况。

### 任务 C：数值字面量补全（G-03 + L-161，中优先级）

**目标**：支持十六进制、二进制、八进制整数字面量，与 Python/C 对齐。

**最小复现（当前报错或静默错误）**：
```光明
设 h 为 0xFF    # 可能解析错误或被当标识符
设 b 为 0b1010  # 可能解析错误
设 o 为 0o644   # L-161 已确认不支持
```

**期望语法**：
```光明
设 h 为 0xFF      # 十六进制 → 255
设 h2 为 0x1a2b   # 十六进制小写 → 6699
设 b 为 0b1010    # 二进制 → 10
设 b2 为 0B1111   # 二进制大写 → 15
设 o 为 0o644     # 八进制 → 420
设 o2 为 0O755     # 八进制大写 → 493
```

**实现要点**：
1. `lexer.py`：`_tokenize_number` 或数字字面量解析分支新增 `0x`/`0X`/`0b`/`0B`/`0o`/`0O` 前缀识别
2. 十六进制：`0x` 后接 `[0-9a-fA-F]+`，生成 Python 十六进制字面量（直接保留 `0x...`）
3. 二进制：`0b` 后接 `[01]+`，生成 Python 二进制字面量（直接保留 `0b...`）
4. 八进制：`0o` 后接 `[0-7]+`，生成 Python 八进制字面量（直接保留 `0o...`）
5. 注意：需与现有数字字面量（整数/浮点/科学计数法 L-085）解析共存，前缀识别应在普通数字解析之前
6. 无效字面量应报明确词法错误（如 `0xGG` 报「无效十六进制字面量」）

**测试用例**：`examples/test_R71_C_数值字面量.light`
- 十六进制（大写/小写/混合/前导零）
- 二进制（大写/小写/前导零）
- 八进制（大写/小写/前导零，含文件权限位场景 `0o644`/`0o755`）
- 与算术运算混合（`0xFF + 1`）
- 与比较运算混合（`0b1010 == 10`）
- 无效字面量报错（反向断言）
- 转字符串后值正确（`转字符串(0xFF)` → `"255"`）

**验收标准**：
- ✅ 上述语法编译通过，运行结果正确
- ✅ L-161 八进制字面量缺陷关闭
- ✅ 现有数字字面量（整数/浮点/科学计数法）不受影响
- ✅ 全量回归零红

**风险评估**：低。数字字面量前缀识别是词法器标准功能，Python 后端直接透传即可。

### 任务 D：字符串能力补全（G-04，中优先级） ✅ 已完成（2026-09-19）

**目标**：支持原始字符串、多行三引号字符串、格式化说明符，消除字符串处理样板。

**最小复现（当前报错或行为不符）**：
```光明
设 路径 为 r'C:\Users\name'  # 原始字符串可能不支持，\U 被当转义
设 多行 为 '''第一行
第二行'''                      # 三引号多行字符串可能不支持
设 格式 为 "{值:.2f}"          # 格式化说明符可能不支持
```

**期望语法**：
```光明
# 原始字符串（反斜杠不转义）
设 路径 为 r'C:\Users\name\dir'  # 原样保留反斜杠
设 正则 为 r'\d+\.\d+'            # 正则表达式无需双重转义

# 多行三引号字符串
设 多行 为 '''第一行
第二行
第三行'''

# 格式化说明符（f-string 风格）
设 pi 为 3.14159
打印("{pi:.2f}")     # 输出 3.14
打印("{pi:>10.2f}")  # 右对齐，宽度10，2位小数
```

**实现要点**：
1. **原始字符串**：`lexer.py` `_tokenize_string` 新增 `r'...'` / `r"..."` 前缀识别，字符串内反斜杠不做转义处理（原样保留）
2. **多行三引号**：`lexer.py` 新增 `'''...'''` / `"""..."""` 识别，字符串内可包含换行（无需续行），生成 Python 三引号字符串
3. **格式化说明符**：`parser_expr.py` `_parse_string_interpolation` 扩展 `{表达式:格式说明}` 解析，格式说明部分透传给 Python f-string（生成 `f"{expr:spec}"`）
4. 注意：原始字符串前缀 `r` 需与现有字符串前缀（如 `b'...'` 字节串 L-159）共存，前缀识别应统一处理
5. 三引号字符串需与现有单引号/双引号字符串共存，词法器需识别三个连续引号

**测试用例**：`examples/test_R71_D_字符串能力.light`
- 原始字符串（Windows路径/正则/含反斜杠）
- 原始字符串前缀大小写（`r'...'` / `R'...'`）
- 多行三引号字符串（含换行/缩进/特殊字符）
- 三引号单双引号（`'''...'''` / `"""..."""`）
- 格式化说明符（`.2f` / `>10` / `<10` / `^10` / `+d` / `,` 千分位）
- 格式化说明符与变量插值混合（`{x:.2f} {y}`）
- 现有 `{变量}` 插值不受影响

**验收标准**：
- ✅ 上述语法编译通过，运行结果正确
- ✅ 现有单引号/双引号字符串、`{变量}` 插值不受影响
- ✅ 全量回归零红

**风险评估**：中。三引号字符串的词法识别需谨慎（三个连续引号的边界判定），格式化说明符需确保不破坏现有 `{变量}` 插值。建议分步实现：先原始字符串（最简单），再三引号，最后格式化说明符。

**交付记录（2026-09-19，R71-D）**：
- **现状核查**：原始字符串 `r/R'...'`（lexer r 前缀 + `_tokenize_string(raw=True)`）、字节串 `b/B'...'`（v7 新单 H）、多行三引号 `'''/"""`（`_tokenize_string` 三引号块消费）、标识符式格式说明符 `{x:.2f}`（`_parse_string_interpolation` + codegen f-string 透传）均已落地并实证通过。
- **本轮补齐**：**数字字面量** + 格式说明符 `{3.14159:.2f}` / `{0xFF:04X}` / `{1234567:,}` 此前不生效（被 `_try_parse_interp_expr` 的 L-086/JSON 字面量防御整串拒绝），现以「数字字面量 + 冒号后为合法格式说明」为双重闸门放行（`parser_expr.py` `_parse_string_interpolation` 的 `_spec_is_valid` + `_try_parse_interp_expr(allow_literal=)`），**词法/代码生成零改动**。

### 任务 E：stdlib 原语补全（L-160 + L-174，中优先级）

**目标**：补齐常用 stdlib 原语，消除用户层重复实现。

**最小复现（当前 NameError）**：
```光明
设 id 为 随机UUID()     # NameError: name '随机UUID' is not defined
设 home 为 主目录()      # NameError: name '主目录' is not defined
```

**期望语法**：
```光明
# UUID 生成（对齐 Python uuid.uuid4()）
设 id1 为 随机UUID()           # 返回 36 位标准 UUID 字符串，如 "a1b2c3d4-..."
设 id2 为 随机UUID()           # 每次调用不同
断言为真(id1 != id2, "UUID唯一性")
断言为真(字符串长度(id1) == 36, "UUID长度")

# 主目录（对齐 Python os.path.expanduser("~")）
设 home 为 主目录()            # 返回当前用户主目录路径
设 配置路径 为 主目录() + "/.config/app"
```

**实现要点**：
1. **随机UUID()**：
   - `stdlib/builtins.py`：新增 `def 随机UUID(): return str(uuid.uuid4())`
   - `stdlib/内置核心工具.light` 或对应模块：新增光明层包装
   - `code_generator.py` / `code_generator_unified.py`：`builtin_map` 注册 `随机UUID` → `_light_builtin.随机UUID`
