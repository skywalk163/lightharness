## 0. 结论先行

1. **19 条全部读完并逐条判定**：需移植 **11** 条、登记不移植 **6** 条、无承载/不适用 **2** 条。
2. 需移植的 11 条里，**forge 三条（快照概览 / diff 定 head / 评审读取）是同一处面的连续扩张**，应合成一张卡落 `src/变更请求.light`；
   其余 8 条各自小而独立。
3. **没有一条会导致 lightharness 现有代码「跑不起来」**——它们都是 TypeScript 侧的签名/字段/错误码变更，光明语言没有静态类型检查，
   所以「不移植」的代价是**语义漂移**（例如快照缺 `threadsTruncated` 就无法表达「未解决数只是下限」），而不是编译失败。
4. 判断「需不需要移植」的口径：**纯逻辑语义是否可复现且有承载体**。宿主接线（Cordis 服务、Remote 命名空间、macOS helper、React 浮层）
   一律登记不移植；没有对应层的（账号通知、DSH skill 目录）明确写「无承载」，**不硬造模块**。
5. 交叉影响：`web-search-billing` 与 `plugin-update-method` 会改变**模型面文案与错误分类**，属于会影响判据的语义变更，优先级高于其余。

## 2. 需移植条目逐条展开（11 条）

### 2.1 #3 archive-worktrees（工作树清理判定）

- **上游语义**：归档 Session 时，若①没有未归档 Session 引用该检出目录；②创建者策略不是只读；③Git 未发现跟踪文件改动、未跟踪文件、
  已初始化子模块、锁、分离 HEAD —— 就 `git worktree remove`（不带 force）。**被忽略的文件（如 `node_modules`）不保留**，
  skip-worktree / assume-unchanged 的改动也不保留；含已提交内嵌仓库的目录 Git 会拒绝删除，于是保留并报清理失败。分支与提交始终保留。
  `retainOnArchive` 默认关；本版本之前的检出目录没有 `plugin:worktree/created` 事件，不会被扫描。
- **落点**：`src/工作区变更.light` 增「工作树清理判定」段落组（判定输入为一份 git 状态快照，输出「可删除/保留 + 原因」）。
  git 命令执行、事件记录属宿主，登记不移植。
- **判据建议**：六类拒绝条件各一例 + 「忽略文件不保留」+ 「内嵌仓库→保留」+ `retainOnArchive` 开关。

### 2.2 #4 attachment-error-codes（附件错误码）

- **上游语义**：`AttachmentError` 现继承 `HarnessError`（`name` 与 `ATTACHMENT_*`/图像准入码不变）。两类持久化结果变化：
  ①适配器读图失败导致模型请求失败时，`turn/end` 的 `code` 从 `UNKNOWN` 变为具体附件码
  （`ATTACHMENT_NOT_FOUND` / `ATTACHMENT_CORRUPT` / `ATTACHMENT_READ_FAILED` / `INVALID_IMAGE` / `IMAGE_TOO_LARGE` 等）；
  ②工具主体逸出 `AttachmentError` 时，`tool/result` 记录 `error:{name:'AttachmentError', code}`（此前无 `error` 字段）。
  `instanceof HarnessError` 现在匹配它；`isAttachmentError` 不变。旧日志仍是 `UNKNOWN`，读方应视为同一类失败。
- **落点**：`src/附件准入.light` 补「错误码归类」（`错误值 → 附件码|空`）；`src/错误增强.light` 补「失败分类优先级」——
  先判 `AttachmentError` 再判 `HarnessError`（指南迁移第 2 条就是这条）。
- **判据建议**：五个码各一例 + `isAttachmentError` 真/假 + 「旧 UNKNOWN 与新码同归类」。

### 2.3 #9/#10/#11 forge 三条（合成一张卡）

- **#9 概览**：`ChangeRequestSnapshot` 新增 7 个**必填**字段：`reviewers`/`reviewersTruncated`、`closingIssues`/`closingIssuesTruncated`、
  `branchUpdates`、`canRequestReviews`、`canRerunChecks`；`ChangeRequestCheck` 新增必填 `rerun: ForgeCheckId | null`
  （`null` = 提供方无法重跑）；`ForgeActionFailure.code` 新增 `unknown`（主机答复无法确认结果，改动**可能已生效**，
  核对前不要重试）。平台无数据时的缺省值是指南给定的那一组（空数组 / `false`）。
- **#10 定 head**：`diff(ref, headSha, signal)`；只有补丁描述该 `headSha` 才返回，否则 `{code:'stale'}`。
  `ChangeRequestSnapshot` 新增必填 `threadsTruncated`（未解决数只是下限时为真）；Remote 侧以 `forgePanel/stale-head` 拒绝。
- **#11 评审读取**：新增 `ctx.forge.readReview(ref, headSha, signal)` ↔ 可选 `ForgeProvider.readReview`；
  提供方不支持时返回 `unsupported`（**能力缺失，不是可重试失败**；对比 `fetchChecks` 未实现仍返回 `unavailable`）。
- **落点**：全部进 `src/变更请求.light`（现有导出只有 键/轮询延迟/URL身份/绑定/推送/评审归一，尚无快照构造）。
  新增段落组前缀 `变更请求快照`，避免与既有 `评审归一` 撞名。
- **判据建议**：缺省快照那 7 个字段逐字段断言；`rerun: null` 语义；`unknown`/`stale`/`unsupported` 三码的分支；
  head 不匹配 → `stale` 且**不返回旧 head 的补丁**。

### 2.4 #12 plugin-update-method（插件更新方式）

- **上游语义**：`listBundles()` 不再返回 `updatable: boolean`，改返回可选 `update`：`listVersions` 能读到更新版本的 → `'registry'`；
  从固定到完整提交的 Git spec 安装的 → `'git'`；`updateBundle` 无法替换的不含该字段。
  `ManagementError` 新增 `unexpected-package`：带 `InstallBundleOptions.expected` 的安装（`updateBundle` 总会传）在
  spec 实际装成**别的包或别的版本**时以此码失败。注意：`plugin_manager` 工具本身从未返回该字段，不受影响。
- **落点**：`src/插件注册表.light`（现有导出：`选首个响应注册表`/`造安装规格`/`归类安装失败`/`推导启停后清单`）——
  补「更新方式判定」到 `造安装规格`/新增段落，补 `unexpected-package` 到 `归类安装失败`。
- **判据建议**：registry/git/无字段 三态；`expected` 不符 → `unexpected-package`；旧 `updatable: true` 映射到 `registry`。

### 2.5 #13 runtime-context-reminders（运行时上下文提醒）

- **上游语义**：新写入且 `source.kind:'runtime-context'` 的 `user/message` 把文本包进 `<system-reminder>`；
  首份快照介绍当前会话、**不宣称覆盖更早上下文**；后续快照明确覆盖「对话摘要保留的上下文」；
  清空提醒携带 `form:'snapshot'` 与 `sections:[]`。无 `source.sections` 的旧快照/清空标记在**下次获准请求**刷新一次
  （加一条消息，但不改写现有请求前缀）；旧快照条目未变则不因文案刷新。`renderContextSnapshot()`/`joinContextSections()` 不变。
- **落点**：`src/会话日志深化.light`（日志写入侧）或 `src/时间上下文.light`（上下文快照侧）——**B 路落地前需先确认**
  本仓「运行时上下文」到底由哪个模块生成（目前两处都有相关段落，避免双写）。
- **判据建议**：首份/后续两种引导语；清空标记形状；旧记录刷新一次且只一次。

### 2.6 #14 session-append-overloads（批量追加）

- **上游语义**：`Session.append` 现在既能收「一个带类型的事件调用」，也能收「事件元组数组」。普通单事件调用仍编译。
  赋值给 `Session['append']` 的替身/包装必须支持两种重载：单事件调用返回**一个事件**，数组调用返回**数组**。
- **落点**：`src/会话.light`（`记录事件(类型, 数据)`）与 `src/会话日志深化.light`（`追加事件(日志, 类型, 载荷, 时间戳)`）——
  两处都补「批量形参」，保持单事件路径返回单条。日志格式不变（指南明确）。
- **判据建议**：单事件返回非数组、数组返回同长数组、空数组、批量内序号连续、失败不改写已有事件。

### 2.7 #15 subagent-interrupt-default（默认关闭中断）

- **上游语义**：base 组合包与 Web 的 `standard`/`cordis`/`ptc` preset 给 `tool-subagent-control` 行设 `config.interrupt: false`，
  于是模型工具定义里**没有** `interrupt_agent`（含 Team 模式）；消息、发现、收件箱等待与 subagent 服务的中断 API 仍可用；
  **插件自身默认值仍为 true**，省略该配置的独立组合仍提供中断工具。
- **落点**：`src/子代理预设选择.light`（`预选*` 一组）与 `src/代理团队.light` —— 补「内置组合默认 interrupt=false」与
  「工具清单是否含 `interrupt_agent`」的判定；注意区分「插件默认」与「内置组合默认」两个层次。
- **判据建议**：内置默认 → 无 interrupt_agent；显式 true → 有；省略 → 有；Team 模式同规则。

### 2.8 #16 terminal-backend-cleanup-error（终端清理失败）

- **上游语义**：PTY 后端启动失败**且清理部分资源也失败**时抛 `TerminalBackendCleanupError`。它从继承 `AggregateError`
  改为继承 `TerminalError`，即带 `CLEANUP_FAILED` 的 `HarnessError`；工具结果记录 `error.name` 与 `error.code`。
  构造函数、`name`、`spawnError`、`cleanupError` 与**按原顺序**的 `errors` 列表不变；`errors` 类型 `any[] → readonly unknown[]`；
  `cause` 是同样两个失败组成的 `AggregateError`。`instanceof AggregateError` 现在为 false。
- **落点**：`src/终端.light`（现只有清理请求 save/remove/pending，**没有错误类型**）补错误构造与码；
  `src/错误增强.light` 补「错误值 → 码」归类。宿主侧 PTY spawn 登记不移植。
- **判据建议**：`CLEANUP_FAILED` 码；`spawnError`/`cleanupError` 保真；`errors` 顺序；不再按 AggregateError 匹配。

### 2.9 #18 web-search-billing（按计费方式选凭据）

- **上游语义**：`web-deepseek-api` 新增 `searchBilling` / `fetchBilling`，取 `auto`（默认）/`account`/`api-key`。
  `auto` 下：DeepSeek 模型路由行为不变；其他会话与会话外操作在**没有密钥时改用已登录账号**；`account` 只用账号；`api-key` 只用密钥。
  非空的 `*BaseURL`/`*ApiKeyEnv` 仍优先。TS 侧 `DeepSeekSearchApiOptions`/`DeepSeekFetchApiOptions` 去掉顶层 `baseURL`，
  `auth` 改为 `{sources, missingCredentialMessage?}`：**每个来源自带地址，列表顺序取代「账号优先」的隐式顺序**；
  来源 `kind` 可以是 `account`/`api-key`/`misconfigured`（只有轮到它才失败）。凭据读取错误保留原始 `Error` 作 `cause`、
  不再多包一层；解析函数抛 `AbortError`（即使 signal 未取消）现在返回 `WEB_ABORTED` 而非 `WEB_PROVIDER_ERROR`。
- **落点**：`src/网页搜索.light`（683 行，已有去重/合并/截断/provider 归一）新增「计费方式 → 凭据来源解析」段落组；
  真实 HTTP 与账号服务宿主登记不移植。
- **判据建议**：三态 × 有无密钥 × 是否模型路由的矩阵；有序来源首个可用者胜；`misconfigured` 只在轮到时报错；
  `AbortError → WEB_ABORTED`。

## 4. 无承载 / 不适用（2 条）

| # | 条目 | 结论 |
