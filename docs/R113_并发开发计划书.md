### R1・轨道 E：修 0.86 LH 剩余 5 红（cwd 相对路径） — **lightharness 仓**

**根因（已定位）**
- `src/插件启停.light:31` `缺省映射路径()`：
  ```light
  设 兄弟 为 路径连接("..", "lightplugin")
  设 集成 为 路径连接(兄弟, "集成")
  返回 路径连接(集成, "工具总表.json")
  ```
  这是**相对当前工作目录**的解析。`lightharness/tests/test_回归.py` 在隔离临时目录里跑 example，临时 cwd 下 `../lightplugin` 不存在 ⇒ `加载插件映射()` 返回 `{}` ⇒ 0 个插件注册 ⇒ 依赖插件工具名的 5 个用例全红。
- `运行.py:27` 已算出**绝对** `LIGHTPLUGIN = os.environ.get('LIGHTPLUGIN', normpath(join(ROOT,'..','lightplugin')))`（`运行.py:41` `jicheng = join(LIGHTPLUGIN,'集成')`、`运行.py:44` `plugins_dir = join(LIGHTPLUGIN,'插件')`），但**没有把 `LIGHTPLUGIN` 写进子进程环境**——所以 `.light` 侧读不到它，只能退回 cwd 相对的 `..`。

**要做**
1. `运行.py`（在 `LIGHTPLUGIN = ...` 之后，约 :27 后）加一行把绝对路径导出给子进程：

   ```light
     如果 覆盖 != "":
       返回 覆盖
     设 根 为 环境变量("LIGHTPLUGIN", "")
     如果 根 != "":
       返回 路径连接(根, "集成", "工具总表.json")
     # 兜底：仅当 LIGHTPLUGIN 未设（裸跑 .light）时退回 cwd 相对
     设 兄弟 为 路径连接("..", "lightplugin")
     设 集成 为 路径连接(兄弟, "集成")
     返回 路径连接(集成, "工具总表.json")
   ```
3. **核验真实调用路径**：确认 `test_回归.py` 经 `运行.py` 起编译器（若不经 `运行.py`，`LIGHTPLUGIN` 环境变量不会自动出现在子进程，需额外把 `LIGHTHARNESS_ROOT` 也导出并在 `.light` 侧据此拼 lightplugin；以 5 个用例复跑结果为准，不要猜）。

### R2・轨道 C：LP-D-012 第二缺口 — async 入口驱动 `asyncio.run` 对齐 — **light-merge 仓**

**根因（已定位）**
- 入口驱动只认同步主入口：`src/code_generator_unified.py:687-713`（**ANTLR 后端**，被 `cli/light_unified.py:232` `UnifiedCodeGenerator` 调用）与 `src/code_generator.py`（**SRC 后端** `PythonCodeGenerator`）各自的「自动入口包裹」块，都只处理 `主程序`/`mean` 且**裸调用 `<main>()`**，从不为 async 主入口包 `asyncio.run(...)`。
- 代码生成器已能感知异步：`code_generator_unified.py:728` `if self._needs_asyncio:` 按需插 `asyncio` 导入；但 `__main__` 驱动段（:707-713）没有据此改成 `asyncio.run(<main>())`。结果：顶层 `异步 段落 主(): …` + `主()` 时，产物是裸 `主()` ⇒ `coroutine '主' was never awaited`（RuntimeWarning，且逻辑不执行）。
- R112-R3 已修 `_resolve_name` 对 `等待 X()` 的 `TypeError`（commit 待收口），但**未修入口驱动这一层**。

**要做**
1. 在**两个**生成器的入口驱动块（unified :707-713；`code_generator.py` 里等价块）增加「主入口是否 async」判断：
   - 判断依据：从 `self.user_functions` 元数据（`user_functions` 应带 async 标记；若未带，按 `_needs_asyncio` + 主函数名推断）确认主入口为 `异步 段落`。
   - 若是 async 主入口，生成 `asyncio.run(<main>())` 而非 `<main>()`；同步主入口维持 `<main>()`。
   - 若 `__main__` 块内用了 `asyncio.run`，确保文件头已 `import asyncio`（与 `_needs_asyncio` 插入逻辑复用，不要重复 import）。
2. **不破坏同步入口**：`主程序`/`mean` 同步写法产物必须逐字节不变（回归用例已覆盖）。

**验收（逐条）**
- 最小复现（≤12 行）`async_demo.light`：
  ```light
  异步 段落 主():
     等待 异步睡眠(0.01)
     打印("ok")
  主()
  ```
  - SRC 后端（默认 `light run async_demo.light`）：**rc=0 且输出 `ok`**，无 `coroutine was never awaited` 警告。
  - ANTLR 后端（`light run async_demo.light --backend antlr` 或 `light compile --backend antlr` 后跑产物）：同样 rc=0 + `ok`。
- LM/LH 门禁**不新增红**（`new_reds == 0`）。

**反跑判据**
- 修前：`async_demo.light` 在双后端均「无 ok 输出 / 报 never awaited」。
- 修后：双后端均输出 `ok`，rc=0。
- 另跑一条原有同步主入口 example（如 `examples/*` 中任一 `主程序`/`mean` 写法）确认产物未变、rc 不变。

**砍线**：若 `user_functions` 元数据不含 async 标记、需改 AST/parser 才能可靠判断主入口是否 async，则**只交付定靶结论 + 最小复现**，登记缺口层级，不在本轮改 AST（避免与 R1/收口窗口冲突）。
