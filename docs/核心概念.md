# 核心概念

lightharness 用「光明」中文编程语言 1:1 复刻 DeepSeek Harness 的 agent 智能体框架。理解以下七大核心概念，即可掌握整个系统的运作方式。

---

## 1. 会话（Session）—— append-only 事件日志 + surface 投影

会话是 lightharness 的核心数据结构，采用**事件溯源（Event Sourcing）**模式：

- **事件表**：所有发生过的事情都以事件形式追加（append-only）到事件表中，每条事件包含 `类型`、`序号`、`时间`、`数据`。
- **不可变**：事件一旦写入不可修改，保证历史可追溯、可重放。
- **surface 投影**：从事件表中筛选出模型可见的消息事件（`user/message`、`assistant/message`、`tool/result`），投影为 LLM 对话历史。

**事件类型**：

| 类别 | 事件类型 |
|------|----------|
| 轮次边界 | `turn/start`、`turn/end` |
| 步骤边界 | `step/start`、`step/end` |
| 消息 | `user/message`、`assistant/chunk`、`assistant/message`、`tool/call`、`tool/result` |
| 请求 | `request/header`、`request/context` |

**源码**：`src/会话.light`

---

## 2. 轮次 / 步骤（Turn / Step）—— agent-loop 结构

代理循环（agent-loop）驱动整个对话流程，采用两层循环：

```
驱动(用户文本)
└── turn/start
    ├── user/message（记录用户输入）
    └── while 进行中:
        ├── step/start
        │   ├── 从事件日志投影出模型历史
        │   ├── LLM 流式请求 → assistant/chunk* → assistant/message
        │   ├── 若含 tool-call → 工具执行 → tool/call* → tool/result*
        │   └── 决定继续/结束
        └── step/end
    └── turn/end（reason: completed / max-tokens / max-steps / error）
```

- **轮次（turn）**：一次用户输入到代理最终回复的完整过程。
- **步骤（step）**：一轮中的一次 LLM 请求 + 工具调用循环。一轮可能包含多个步骤（模型调用工具后继续推理）。
- **max-tokens 粘滞**：任一步骤触顶，整轮结束原因保持 max-tokens。
- **溢出重试**：LLM 返回上下文溢出错误时，自动压缩后重试，最大重试次数和间隔可配置。

**源码**：`src/代理.light`（同步）、`src/异步代理.light`（异步）

---

## 3. 工具（Tools）—— 注册 / 执行 / 统计

工具系统让 agent 能够调用外部能力（执行命令、读写文件、查询数据库等）。

- **注册**：每个工具有名字、描述、参数模式（JSON Schema）、执行函数、并发策略（exclusive 串行 / parallel 并行）。
- **执行**：模型返回 tool-call 后，代理按序分组执行；exclusive 工具形成串行屏障，parallel 工具分批并发执行（线程池限流）。
- **统计**：工具注册表维护调用次数、成功/失败计数，供遥测模块采集。

**示例**：

```light
从 工具 导入 工具注册表, 造工具定义

设 注册表 为 新建 工具注册表()
注册表.注册(造工具定义(
  "bash",
  "执行 shell 命令",
  ["type": "object", "properties": ["command": ["type": "string"]]],
  执行bash
))
```

**源码**：`src/工具.light`

---

## 4. 事件溯源（Event Sourcing）—— 事件表 / 投影 / 压缩替换

lightharness 的状态全部来自事件日志，不维护独立的可变状态：

- **事件表**：唯一的真相来源（single source of truth），append-only。
- **投影（Projection）**：`整理消息()` 从事件表投影出当前模型可见的消息序列。
- **压缩替换（Compaction）**：当消息过长时，将最旧的连续会话段折叠为一条「压缩摘要」用户消息，通过 `压缩替换` 遮蔽旧事件（旧事件保留可追溯的来源序号），不删除历史。
- **持久化**：事件日志以 JSONL 格式增量写入磁盘，支持断点续写。

**压缩触发时机**：
1. step 前自动检查 token 压力（超过阈值比例 × 上下文窗口则压缩）
2. LLM 返回上下文溢出错误时，压缩后重试

**源码**：`src/压缩.light`、`src/持久化.light`、`src/会话.light`

---

## 5. 钩子系统（Hooks）—— 三事件域 + 一次性监听器

钩子系统提供事件驱动的扩展机制，分为三个事件域：

| 事件域 | 持久性 | 用途 |
|--------|--------|------|
| **会话事件** | 持久（落 JSONL） | 事实记录、历史重建 |
| **agent 事件**（`agent/*`） | 实时 | 轮次/步骤状态、请求、错误 |
| **能力事件**（`capability/*`） | 实时 | 工具执行、附加策略、适配器 |

- **发布/订阅**：监听器订阅特定事件类型，事件发布时按序回调。
- **一次性监听器**：触发一次后自动移除，适合等待特定事件（如等待工具执行完成）。
- **瀑布事件（waterfall）**：监听器必须调用 `下传()` 才能将事件传递给下一个监听器，支持拦截与修改。
- **串行事件（serial）**：无下传，按注册顺序执行。

**源码**：`src/钩子.light`、`src/事件.light`

---

## 6. 沙箱（Sandbox）—— 路径护栏 + 资源限制

沙箱为工具执行提供安全边界：

- **路径护栏**：所有文件操作限制在授权目录内，禁止越权访问（类似 chroot）。
- **资源限制**：可配置子进程的超时时间、输出大小上限、并发数上限。
- **子进程执行**：通过 `子进程.light` 执行外部命令，捕获 stdout/stderr/退出码。
- **终端 PTY**：`终端.light` 提供真 tty 伪终端，支持交互式程序（需 Win10 1809+ / Unix）。
- **云沙箱**：`e2b客户端.light` 提供 E2B 云沙箱接口层（含本地模拟模式）。

**源码**：`src/沙箱.light`、`src/子进程.light`、`src/终端.light`、`src/e2b客户端.light`

---

## 7. 遥测（Telemetry）—— 调用树 + 指标 + 导出

遥测模块采集 agent 运行时的全链路指标：

- **调用树**：记录轮次 → 步骤 → 工具调用的层级结构，支持耗时分析。
- **指标采集**：
  - 轮次：耗时、输入/输出 token、步骤数、结束原因
  - 步骤：延迟、token 用量
  - 工具：调用名、耗时、成功/失败
- **错误分类**：按错误种类（网络/超时/溢出/参数/其他）聚合统计。
- **导出**：支持导出为 JSON 格式，供外部分析与持久化。
- **持久化接口**：可对接自定义存储后端。

**接入方式**：在代理选项中传入遥测实例，代理循环自动记录。

```light
从 遥测 导入 遥测收集器
设 遥测实例 为 新建 遥测收集器()
设 代理 为 新建 代理循环(会话, 客户端, 注册表, ["遥测": 遥测实例])
```

**源码**：`src/遥测.light`

### 模块依赖关系

```
总入口.light
  ├── 客户端.light (LLM 流式请求)
  ├── 代理.light / 异步代理.light (agent-loop)
  │     ├── 会话.light (事件日志 + surface)
  │     ├── 工具.light (注册/执行)
  │     ├── 流.light (流式词汇表 + 组装器)
  │     ├── 压缩.light (上下文压缩)
  │     ├── 审批.light (用户审批)
  │     ├── 遥测.light (指标采集)
  │     └── 钩子.light (事件域)
  ├── 持久化.light (JSONL 读写)
  ├── 沙箱.light / 子进程.light / 终端.light (运行层)
  └── mcp客户端.light / e2b客户端.light (生态层)
```
