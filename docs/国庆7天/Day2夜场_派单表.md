## 四、Agent 装法（v1.2：优先 5 路并行）

### 4.1 推荐：**5 路并行**（能开 5 个 agent 就用这个）



| Agent   | 子任务         | 独占资源                        | 说明                     |
| ------- | ----------- | --------------------------- | ---------------------- |
| **Ag1** | **T1 → T2** | `src/` + `antlrparser/` + 门 | 唯一真正串行的一路；T1 收口后立刻接 T2 |
| **Ag2** | **T3**      | 1.5 盒子                      | 长等待，不占 CPU             |
| **Ag3** | **T4**      | `_push_*.py` + API          | 长等待，不占 CPU             |
| **Ag4** | **T5**      | `probes/` + 缺陷账             | 轻中 CPU，与 T1 错峰         |
| **Ag5** | **T6**      | `Day11` 文档                  | 纯文档                    |

> **并行解锁点（关键）**
>
> ：
>
> **T1 的探针若判定「已可用 → 销账」，T2 可立即开跑，不必等 T1 的修复**
>
> 。参照 LP-D-011/013 的两次先例，这个概率不低 → Ag1 的实际路径可能是「探针 40 分钟 → T2 1.5 小时」，而不是「修 T1 + 修 T2」。

### 4.2 回退：**3 个 agent**（每人格子内交错，互不阻塞）



| Agent | 槽 1             | 槽 2（交错填空）                  | 为什么能共存              |
| ----- | --------------- | -------------------------- | ------------------- |
| **A** | **T1 → T2**     | —（编译器线全程占满）                | 独占 `src/`+ 门，杜绝抢锁   |
| **B** | **T3**（1.5 长等待） | **T4**（API 干跑 + LLM smoke） | 两个端点不同，等 T3 的空档跑 T4 |
| **C** | **T5**（探针 + 账）  | **T6**（Day11 文档）           | 不同文件；文档在探针跑的间隙写     |

## 七、门命令与判据



```
cd lightharness
MSYS_NO_PATHCONV=1 CODEBUDDY_SAFE_DELETE_ENABLED=0 \
  python scripts/082全量回归.py all --mode full --py /usr/local/bin/python3.12
python scripts/082全量回归.py show --recent     # 核对每轮 total/mode/skipped/passed 口径
```

**判据（三元，缺一不可）**：failed 新增 0 **且** skipped 不增 **且** passed 不降。



* **对拍锚点**：`reports/082_lightmerge基线_2026-10-02-171604.json` = **8356 / 0 / 122**（`mode=full`）

* **数字只取门脚本落盘 JSON**：`8355` 是白天 barrier gate3 的 **pytest 汇总行**（`barrierD_gate3_082.txt:483`，同列 `11 xfailed / 2 xpassed`），与同次 JSON 差 2 条是 xpass 计法差异 → **禁止跨运行引用**。

* **禁止&#x20;**`refresh-local`**&#x20;自比当判据**（把新基线写进 latest 再自比，恒为 0、无意义）→ 对拍**时间戳基线**。

* 现行门（`scripts/回归基线.py:187`）**只看 failed 集合**，对「passed 变 skipped」失明 → 三元**必须人工比对**。
