## 四、步骤（对每条重复）

1. **探针**：写最小复现到 `docs/国庆7天/probes/lp0NN_<主题>.light`（命名沿用现有 6 个探针的风格：`lp011_probe.light` / `lp013_probe2.light`）。
2. **跑**：`light-merge/.venv/Scripts/python.exe light-merge/cli/light.py run <探针>`（默认 SRC 后端）；需要时加 `--backend antlr` 对比。
3. **判定**（三选一，必须落一条）：
   - **销账**：不可复现 → 写明「实测不可复现 + 命令 + rc」，并把账内状态改为已销账（**不是删除**，台账惯例是原行转注释 + 判据 + 证据文件名）。
   - **契约纠正**：014/015 这类 → 出口是**文档/契约口径修正**（改哪句、改成什么），并在账内标注「契约纠正，非语言缺陷」。
   - **立账/修复**：016/017 这类若确为真缺陷 → 写明「判定仍待修」+ 探针路径 + 复现命令 + 影响面；**若要提代码修复，见下。**
4. **固化为回归**：把「仍待修」的探针固化成测试（放 `lightharness/tests/unit/` 或 `light-merge/tests/`，与既有 `test_Day4_LP013_探针回归.py` 同风格）。
