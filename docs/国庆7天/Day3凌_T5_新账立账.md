## 二、LP-D-018 · SRC 后端 `返回 <关键字词变量名>` 取不到值

### 2.1 探针

`probes/lp018_返回关键字词变量.light`：

```
段落 乙(值):
    设 跳过 为 []
    跳过.追加(值)
    打印(转字符串(跳过))
    返回 跳过

打印(转字符串(乙(7)))
```

反向对照 `probes/lp018_对照_普通名.light`：把变量名 `跳过` 换成普通名 `列表`，其余结构完全一致。

### 2.2 实测（本批当场跑）

| 探针 | SRC | ANTLR |
|---|---|---|
| `lp018_返回关键字词变量` | rc=0，输出两行：**`[7]` / `None`** ❌ | rc=0，输出两行：**`[7]` / `[7]`** ✅ |
| `lp018_对照_普通名`（对照） | rc=0：`[7]` / `[7]` ✅ | rc=0：`[7]` / `[7]` ✅ |

**定位**：函数内 `打印(转字符串(跳过))` 得 `[7]`（列表内容正确、追加也没问题），
但 `返回 跳过` 到调用方变成 `None`；换成普通变量名则两后端都正常。
⇒ 缺口精准落在「**关键字词作变量名 + `返回` 语句**」这一组合，不是「返回列表」本身。

**与 LP-D-013 的关系**：同族（都是「已声明的关键字词作标识符」），但 LP-D-013 修的是
**成员访问基名位**（`跳过.追加(...)`），本条是 **`返回` 语句位** —— 不是同一个位置，故单独立账。

分开立会让排期碎片化。
