# 国庆 day2 · 派单表（v1.0，2026-10-02）

> 配套计划：`docs/国庆day2计划.md`（**v1.1**）
> 本表用途：把 day2 的 8 条工作流（4 串行线 + 3 轨道 + 1 屏障）装进 **3 个 agent**，同时保持 **6 个子任务在飞**。
> 6 份独立契约：`Day2_契约_S1…S6_*.md`（同目录）。

---

## 〇、一句话

**能同时开 6 个子任务，但不是靠「加进程」**——瓶颈是三样串行资源 + 一样物理资源：**0.82 门（全局唯一）、编译器冻结、team lead 复现位**、以及**本机 10 核的 CPU 余量**。
所以并发上限 = **6 子任务／其中最多 2 个 CPU 型／其中最多 1 个门**。

## 一、资源预算（硬上限，写进每份契约）

| 资源 | 同时上限 | 依据（已实测） |
|---|---|---|
| **0.82 权威门** | **1** | sync 远端目录按秒命名（`scripts/同步0.82.py:255` `/tmp/r44-{YYYYmmdd-HHMMSS}`）+ 写共享指针 `reports/同步0.82_远程目录.txt`（`:303`）+ diff 取「上一份基线 vs 最新」共用 `latest` → 并发必污染基线链 |
| **本机 CPU 重载**（pytest `-n≥4` / bench / 全量 collect） | **1，最多 2**（第二个 ≤2 worker） | `ci_environment_reds.txt`：`-n auto`(10) 轮 4/13/11 红；`-n 8` **挂死 45min+**；`-n 4` 轮 1 红且全在台账内。原话「**-n 4 不是修复：CPU ≥80% 时仍会崩**」。本机 **10 物理核** |
| **1.5 盒子**（192.168.1.5） | **1**（内部子步串行） | 单盒子单链路；且「共享生产盒先预检」铁律（swapinfo / 无 OOM / 无 CI 在跑） |
| **github / gitcode / gitea** | 2–3 可并行（端点不同），API 侧 3–5s 间隔 | 无共享状态；但有速率限制 |
| **team lead 复现位** | **1** | 子代理会谎报 → 必须亲自跑；固定 12:00 / 18:00 两批，每批上限 3 份出口物 |
| **git worktree** | 每子任务 1 个 | 防同树互踩（R109 B 线：报告写了、commit 待填、改动裸在工作树） |

> ⚠️ **「更多进程」为什么不等于更多吞吐**：CPU 型子任务加并发会**制造假红**（xdist worker 被杀 → `[gwN] node down` → `INTERNALERROR … execnet bootstrap io.read(1) got 0`，台账实证曾产出 **507 failed 的中断产物、非真实回归**）。而 I/O 型子任务加并发才有效——本计划恰好大部分是「等网络」。

## 七、附录 A · 证据四件套（每份出口物必须带回）

```
1) 命令        ：可直接复制粘贴的完整命令（含环境变量前缀）
2) 退出码      ：真实 rc（不许只写「成功」）
3) 日志路径    ：**统一落在工作区根 `logs/day2/`**（= `G:\dswork\duan-light-merge\logs\day2\`，跨三个仓共用、不进任何仓的提交），命名 `S<编号>_<用途>.log`；报告里写该路径。**仓库里查不到日志的出口一律不算**
4) 被测 SHA    ：(repo, SHA) —— 例：lightharness 082255c / light-merge d6b84a716
```
> 这一条是 v0.3.0 的教训：Day5 的 rc=0/SSE 200、Day6 的三件套与 11×、Day3 的 1179、Day1 的本机 1171/1957s **在仓库里零日志**；gate3 实际跑的是 LH `b494533`（track-C 分支）而报告声称冻结点 `034a50b9f`，**未注被测 SHA → 无法复核「在冻结基底上验收」**。

## 附录 B · 通用禁止事项（6 份契约全部适用）

1. **禁止 `git push`**（含 github/gitcode/gitea/本地镜像）——等用户示意。
2. **禁止改 `light-merge/src/`、`antlrparser/`**（编译器冻结）；确有需要 → 举手 → 拿门 → 全员暂停（快门条件化）。
3. **禁止 `git checkout -- .` / `git clean -fd`**（R109 B 线教训：会吞掉未提交的真实交付）。
4. **禁止口头结论**：不落盘日志的「已验证」一律不认。
5. **禁止用 `refresh-local` 自比当判据**（台账原话：把新基线写进 latest 再自比，**恒为 0、没有意义**）——要对拍**时间戳基线**。
6. **长跑必须带 `CODEBUDDY_SAFE_DELETE_ENABLED=0`** + `-n 4`；跑前过 `light-merge/scripts/跑前CPU门禁.py`；**长跑独占一个 turn**（护栏是每 turn 50 次删除上限，两个子任务交叉操作会互相顶爆、成片假红）。
7. 看到成片红 → **先怀疑假红三源**（safe-delete / xdist worker 死 / CPU ≥80%），不要报回归。
