## 四、步骤

### A · LP-D-013 ANTLR 缺口 → 给结论（二选一，必须落一条）

1. 跑两例探针的 **ANTLR 后端**复现，把**完整报错**与 rc 落盘。
2. 判定：
   - **立账** → 写明：`xfail` 依据（为什么是预期失败而非真回归）、复现命令、影响面（哪些调用链用 ANTLR 后端会中）、以及**规避写法**（用 SRC 后端或改写代码），并在账内新增/更新 LP-D-013 行。
   - **销账** → 写明为什么不再算缺口（例如：ANTLR 后端不在任何生产链路上、或已由 Day2 的 `尝试/捕获` 收口顺带修好）——**并给证据**，不能只写「影响不大」。
3. 若顺手修了 ANTLR 规则（**不建议在本子任务做**——动 `antlrparser/` 触发冻结+快门）→ 必须先举手拿门。

### B · Day3 账面差（1171 vs 1179）→ 定位并关闭

1. **先确认身份**：核对你复跑所用的 `light-merge` commit，与 `day3-baseline` / Day7 记录的冻结点是否一致（不一致就先说明，不要急着解释差异）。
2. **collect 对拍**：在两个可比对象上各跑一次收集并落盘：
   ```
   cd light-merge
   <venv>/python.exe -m pytest tests/ --collect-only -q -o "addopts=" > logs/day2/S4_collect_<对象>.txt 2>&1
   ```
   然后 **diff 两份清单**，逐条定位「1171 vs 1179」的构成差异。
3. **给结论**：那 1 条（或 8 条）到底是谁引入的、是新增用例、是 collect 条件差异（如 `--ignore` / marker）、还是真漏跑。**关闭该账**（在附件报告里写「已关闭 + 判据 + 证据文件名」）。
