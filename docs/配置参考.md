# 配置参考

本文档列出 lightharness 各模块的配置项。当前版本覆盖遥测模块。

---

## 遥测配置

遥测模块通过 `代理循环` 的 `选项["遥测"]` 传入 `遥测收集器` 实例，或独立使用。配置项如下：

### 遥测.启用

| 项目 | 说明 |
|------|------|
| **默认值** | `true` |
| **取值范围** | `true` / `false` |
| **说明** | 是否启用遥测数据收集。设为 `false` 时，代理循环不记录任何指标。 |

**示例：**
```light
设 代理 为 新建 代理循环(会话, 客户端, 注册表, ["遥测": 遥测实例])
```

### 遥测.输出器

| 项目 | 说明 |
|------|------|
| **默认值** | `console` |
| **取值范围** | `console` / `jsonl` / `otlp`（可多选，逗号分隔） |
| **说明** | 遥测数据输出目标。`console` 输出到控制台；`jsonl` 写入 JSONL 文件；`otlp` 组装 OTLP HTTP 请求结构（接口层预留，未实际发送）。 |

**示例：**
```light
设 管理器 为 新建 输出器管理器()
管理器.注册(新建 控制台输出器(空))
管理器.注册(新建 JSONL输出器("./telemetry/session1.jsonl", 空))
```

### 遥测.JSONL路径

| 项目 | 说明 |
|------|------|
| **默认值** | `./telemetry/{session_id}.jsonl` |
| **取值范围** | 文件路径模板，支持 `{session_id}` 占位符 |
| **说明** | JSONL 输出器的文件路径。每个 span 一行 JSON。路径中的 `{session_id}` 会被替换为实际会话标识。 |

**示例：**
```light
设 路径 为 "./telemetry/sess_001.jsonl"
设 输出器 为 新建 JSONL输出器(路径, 空)
```

### 遥测.OTLP端点

| 项目 | 说明 |
|------|------|
| **默认值** | `""`（空，不启用） |
| **取值范围** | HTTP/HTTPS URL |
| **说明** | OTLP 导出端点。当前为接口层预留，设置后仅组装请求结构，不实际发送 HTTP 请求。 |

**示例：**
```light
设 输出器 为 新建 OTLP输出器("https://otlp.example.com/v1/traces", ["Authorization": "Bearer xxx"], 空)
```

### 遥测.OTLP请求头

| 项目 | 说明 |
|------|------|
| **默认值** | `{}`（空字典） |
| **取值范围** | 字典，键值均为字符串 |
| **说明** | OTLP HTTP 请求头，通常包含 `Authorization` 等认证信息。 |

**示例：**
```light
设 请求头 为 ["Authorization": "Bearer sk-xxx", "Content-Type": "application/json"]
设 输出器 为 新建 OTLP输出器("https://otlp.example.com/v1/traces", 请求头, 空)
```

### 遥测.采集正文

| 项目 | 说明 |
|------|------|
| **默认值** | `false` |
| **取值范围** | `true` / `false` |
| **说明** | 是否在 span 属性中采集提示词/回复/工具参数正文。为 `false`（默认）时，仅保留结构和元数据（token 数、耗时、状态、工具名、参数 hash），不包含正文内容，保护用户隐私。 |

**示例：**
```light
设 遥测 为 新建 遥测收集器()
遥测.配置选项(["capture_content": 假])
```

### 遥测.采样率

| 项目 | 说明 |
|------|------|
| **默认值** | `1.0`（全采样） |
| **取值范围** | `0.0` - `1.0` |
| **说明** | 遥测数据采样率。`1.0` 表示全部记录，`0.0` 表示不记录。当前版本保留配置接口，实际采样逻辑待后续版本实现。 |

**示例：**
```light
# 采样率 0.5 表示约 50% 的 span 被记录
```

## 压缩配置（环境变量，T-0402）

`src/压缩E5.light` 的 `压缩配置解析()` 是**唯一入口**：`压缩管理器` 与 `压缩配置` 的窗口/阈值口径
都从这里取，不再各读一套。三个变量在服务启动/实例构造时读取：

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `HARNESS_MODEL_CONTEXT_WINDOW` | `32768` | 模型上下文窗口（token），用于算使用率与触发阈值 |
| `HARNESS_COMPACTION_THRESHOLD_RATIO` | `0.75` | 触发压缩的用量比例（0~1） |
| `HARNESS_COMPACTION_KEEP_COUNT` | `10` | 压缩后至少保留的最近消息条数（token 口径的兜底） |

```bash
HARNESS_MODEL_CONTEXT_WINDOW=131072 \
HARNESS_COMPACTION_THRESHOLD_RATIO=0.8 \
HARNESS_COMPACTION_KEEP_COUNT=20 \
python3 运行.py examples/运行Web服务器.light
```

口径说明：

- **默认窗口已从 128000 统一为 32768**。此前 `压缩管理器` 与 E5 配置各有一套默认（128000 / 另一路），
  同一进程里两处不一致；T-0402 统一到 32768（对齐 DSH 默认窗口），要更大窗口就显式设环境变量。
- 三个值按 `转整数` / `转浮点` 解析，请填十进制数字串（不要带单位或百分号）。
- 旧键 `HARNESS_COMPACTION_THRESHOLD`（绝对 token 阈值，默认 8000）与
  `HARNESS_COMPACTION_KEEP_ROUNDS`（保留轮数，默认 6）仍然保留：`agent.light` 的滑动窗口压缩与
  `总入口 dump-config` 是锁定消费者，**不要删**；新代码一律走上面的三键。
- `/compact` 手动压缩与自动阈值压缩共用同一份配置；手动入口不消耗模型轮次。

## 运行轮数（T-0439）

| 预算 | 代码常量 | 默认 | 覆盖方式 | 说明 |
|---|---|---|---|---|
| 单轮步数 | `src/步数上限.light` 的 `步数缺省`（`src/代理.light` 只从它取缺省） | `96` | 请求体 `最大步数` 优先；否则读 `HARNESS_MAX_STEPS` | 一步 = 一次模型请求 + 同批工具调用；环境值限 1..1000，非法值回落 96 |
| 目标续跑轮数 | `src/目标续跑.light` 的 `续默认最大轮数` | `64` | 单目标台账 `maxGoalRounds` | 连续无进展阈值 `2` 先生效，空转两轮即停 |

```bash
HARNESS_MAX_STEPS=200 python3 运行.py examples/运行Web服务器.light
```

口径说明：

- 旧默认是单轮 `25` 步、目标 `8` 轮；实测编码类任务常在收口前触顶，T-0439 分别抬到 `96` / `64`。
- 参考 DSH `tool-ralph` 的 `maxRounds` 默认 `256`（`packages/experimental/tool-ralph/src/index.ts:35`）；
  本仓一轮 = 一整轮对话，单位成本更高，故不照抄 256。
- `src/代理循环.light` 的 `默认最大轮次 = 3` 是上游 agent-loop 的纯逻辑复刻，只服务单测，
  **不是**运行时预算，不要拿它调任务长度。
