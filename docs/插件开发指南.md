# 插件开发与使用指南

lightharness 的插件是一段光明语（`.light`）代码，它在启动时把自己的工具注册进 agent 的工具表。agent 调用工具时，实际执行的就是插件里的处理函数。

本文分两部分：

- **用户篇**：怎么在侧栏"插件"面板里启用 / 停用 / 添加插件。
- **开发者篇**（写给人，也写给自动写插件的 agent）：怎么从零写一个能被面板识别、能被 agent 调用的插件。

---

## 一、用户篇：管理插件

打开 lightharness，侧栏点"插件"。你会看到一张卡片列表。

### 1. 启停一个插件

每张卡片右上角有一个开关：

- **开**：该插件的全部工具对 agent 可见、可调用。
- **关**：该插件的工具立即从 agent 工具表里注销，agent 再也看不到也调不到。

切换即时生效，不用重启。状态记在数据根的 `plugins.json` 里，下次启动保持。

### 2. 看插件挂了哪些工具

点卡片展开"工具清单（N）"。这里列出的就是这个插件注册到工具表的所有工具名——agent 实际能调的就是这些名字。

### 3. 通过 GitHub 添加一个新插件（外部插件）

面板顶部有一个输入框：

```
GitHub 地址或 owner/repo，回车添加插件
```

支持三种写法：

| 输入 | 含义 |
|---|---|
| `你的名/插件仓库` | 简写，自动拼成 `https://github.com/你的名/插件仓库` |
| `https://github.com/你的名/插件仓库` | 完整 URL |
| `https://github.com/你的名/插件仓库.git` | 带 `.git` 后缀也行 |
| `git@github.com:你的名/插件仓库.git` | SSH 地址也行 |

回车后 lightharness 会：

1. `git clone --depth 1` 把仓库拉到 `lightplugin/插件/_外部/<仓库名>/`；
2. 自动找仓库根目录的入口 `.light`（优先与仓库同名，否则第一个非测试 `.light`）；
3. 记入数据根的 `installed.json`；
4. 清缓存，下一次请求就把这个插件挂上。

之后它出现在卡片列表里，名字后面带"（外部）"，和内置插件一样可以启停。

> **前提**：被 clone 的仓库必须是光明插件格式（见下文"开发者篇"）。仓库根目录要有一个暴露 `挂载(注册表)` 的 `.light` 文件。上游 deepseek-harness 的 JS/TS npm 插件**不能**这样装——本运行时是 Python，没有 Node/Cordis 加载器。

### 4. 卸载外部插件

目前面板没有卸载按钮。要移除一个外部插件：

1. 删掉数据根 `installed.json` 里对应那条；
2. 删掉 `lightplugin/插件/_外部/<仓库名>/` 整个目录；
3. 重启 web。

## 二、开发者篇：写一个插件

### 1. 插件长什么样

一个插件就是一个目录：

```
lightplugin/插件/我的插件/
├── 我的插件.light      # 主文件：必须暴露 挂载(注册表)
├── 测试_我的插件.light  # 自测脚本（可跑 `python 运行.py examples/...` 风格）
└── 说明.md             # 给人看的：干什么的、工具名、参数
```

命名约定：

- 目录名 = 主文件名 = 插件名（中文也行）。
- 测试文件以 `测试_` 开头，加载器会跳过它。
- 说明.md 写一句话用途 + 每个工具的参数。

### 2. 最小可跑模板

把下面存成 `lightplugin/插件/问候器/问候器.light`：

```light
# 问候器.light —— 最小插件模板
从 工具 导入 造工具定义, 造工具结果

段落 问候器处理(参数):
  设 名字 为 参数.获取("名字", "朋友")
  返回 造工具结果("你好，" + 名字 + "！这是问候器插件回的。")

# 挂载(注册表) 是唯一必须导出的入口。
# 启动时 lightharness 会调它，把你注册的工具塞进 agent 工具表。
段落 挂载(注册表):
  注册表.注册(造工具定义(
    "问候",
    "向指定的人打个招呼。参数：名字（字符串，可选）",
    {"名字": {"类型": "字符串", "描述": "要问候的对象", "可选": 真}},
    问候器处理
  ))

导出 问候器处理
```

就这一个文件，重启后 agent 的工具表里就多了一个 `问候`。

### 3. API 速查

| 你要做 | 用什么 |
|---|---|
| 声明一个工具 | `注册表.注册(造工具定义(名, 描述, 参数模式, 处理函数))` |
| 处理函数返回成功 | `造工具结果(文本)` |
| 处理函数返回结构化 | `造工具结果(文本, 额外字典)` |
| 读参数 | `参数.获取("键", 默认值)` |
| 读 JSON | `从 JSON 导入 解析JSON, 序列化JSON` |
| 读写文件 | `从 文件系统 导入 读取文件, 写入文件, 文件存在, 路径连接` |
| 跑外部命令 | `从 外部命令 导入 执行命令, 命令存在` |
| 发 HTTP | `从 HTTP客户端 导入 ...`（按需） |

**处理函数签名固定**：`段落 某工具处理(参数)`，返回值用 `造工具结果(...)` 包起来。

### 4. 写测试

`测试_问候器.light`：

```light
从 问候器 导入 问候器处理

设 结果 为 问候器处理({"名字": "世界"})
如果 字符串包含(结果["内容"], "世界") == 假:
  抛出 "FAIL：问候器没回名字"
打印 "问候器测试 PASS"
```

跑法和其他示例一样：`cd lightharness && python 运行.py ../lightplugin/插件/问候器/测试_问候器.light`（路径按你的部署调）。

### 5. 让面板识别你的插件

- **内置插件**：放进 `lightplugin/插件/<名>/`，并在 `lightplugin/集成/工具总表.json` 里登记一行 `"<名>": ["工具名1", "工具名2"]`——面板靠这张表显示工具数和工具清单。不登记也能挂载，只是面板里工具数显示 0。
- **外部插件**：推到 GitHub，仓库根目录就是 `<名>.light`（或任意 `.light`），别人在面板输入框填 `owner/repo` 即可。

### 6. 启停怎么生效的（给调试的人）

启动流程里，`总入口.组装注册表(预设标识, 数据根)` 会：

1. 挂核心工具；
2. 静态挂 `lightplugin/集成/生产挂载.light` 里登记的内置插件；
3. 动态补挂 4 个与宿主同名的"撞车"插件（按文件路径编译加载，绕开裸名 import 冲突）；
4. 读 `installed.json`，动态加载外部插件；
5. 读 `plugins.json`，把被停用插件的工具名从注册表里注销。

状态文件位置（数据根下）：

| 文件 | 内容 |
|---|---|
| `plugins.json` | `{"插件名": false}`，键缺失 = 默认启用 |
| `installed.json` | 外部插件清单 `[{"name, 路径, 入口}]` |

### 7. 常见坑

- **不要用 `模块` 当变量名**——光语保留字，用 `插件模块`。
- **字符串操作是函数式的**：`截取(串,起,止)`、`结尾(串,后缀)`、`字符串包含(串,子)`、`分割字符串(串,分隔)`、`去除空白(串)`，不是方法链。
- **`路径连接` 只收 2~3 个参数**，拼长路径分段拼。
- **写 `.light` 文件用无 BOM 的 UTF-8**。PowerShell `Set-Content -Encoding UTF8` 会写 BOM，光语词法器不接受；用 `[IO.File]::WriteAllText($p,$t,(New-Object System.Text.UTF8Encoding($false)))`。
- **捕获异常语法**是 `捕获 异常 e:`，不是 `捕获 错误:`。
- **插件内部互相 import** 时，加载器会把插件模块注册进 `sys.modules`，兄弟插件之间 `从 兄弟插件 导入 ...` 能命中插件版而不是宿主残骸。

## 三、一页清单（给 agent 自动写插件）

接到"写一个插件做 X"的任务时，按这个顺序：

1. 在 `lightplugin/插件/<插件名>/` 建目录。
2. 写 `<插件名>.light`：
   - `从 工具 导入 造工具定义, 造工具结果`；
   - 每个能力一个 `段落 <名>处理(参数)`，返回 `造工具结果(...)`；
   - 一个 `段落 挂载(注册表)`，里面 `注册表.注册(造工具定义(...))` 每个工具调一次；
   - `导出` 处理函数。
3. 写 `测试_<插件名>.light`：直接调处理函数，断言返回内容。
4. 写 `说明.md`：一句话用途 + 工具名 + 参数表。
5. 跑测试，PASS 为止。
6. 在 `lightplugin/集成/工具总表.json` 登记插件名 → 工具名列表（这样面板显示工具数）。
7. 如果是要分发的外部插件，推到 GitHub，仓库根目录放 `<插件名>.light`。
