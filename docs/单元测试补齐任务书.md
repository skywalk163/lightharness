# lightharness 单元测试补齐任务书（B 档：核心业务模块单测）

> 目标：为 ~33 个核心业务模块补 deepseek-harness 风格的包内单测。
> 路线：黑盒 .light 片段（路线1）为主；纯逻辑模块可在片段内直接断言。
> 基建：`tests/unit/test_support.py` 已就绪，smoke test 3/3 通过。

## 基建用法（必读）

```python
# tests/unit/test_xxx.py
from test_support import run_light_source, assert_success, out_contains

def test_某函数():
    r = run_light_source('''
从 字典增强 导入 字典合并
段落 主程序:
  设 c 为 字典合并({"a":1}, {"b":2})
  打印("RESULT=" + 转字符串(c))
''')
    assert_success(r)
    out_contains(r, "RESULT=")
```

- `run_light_source(source, timeout=60)` → LightResult(rc, stdout, stderr, workdir)
- `assert_success(r)` / `assert_failure(r)` / `out_contains(r, needle)` / `out_not_contains(r, needle)`
- .light 片段里 `从 <模块名> 导入 <符号>` 即可引用 src/ 下模块
- 每个用例在隔离临时目录跑，文件副作用不污染仓库
- 需要保留工作目录排查时设环境变量 `LKEEP=1`

## 编写规范

1. 一个模块一个测试文件：`tests/unit/test_<模块名>.py`
2. 每个文件 8–20 个测试函数，覆盖：
   - 正常路径（至少 3 个用例/函数）
   - 边界/空值/异常输入
   - 反向哨兵（应报错的输入 rc!=0，用 assert_failure）
3. .light 片段里用 `打印("KEY=value")` 输出关键中间值，Python 侧断言
4. 不要起网络/服务器/长驻进程；需要 IO 的模块用临时目录
5. 不要修改 src/ 下任何源码——只写 tests/unit/ 下的测试文件
6. 跑完必须自验：`python -m pytest tests/unit/test_<模块名>.py -o addopts="" -v`

## 验收标准

- 每个测试文件全部通过（rc=0）
- 不破坏现有门禁（`python -m pytest tests/test_回归.py -o addopts=""` 不新增红）
- 测试有断言价值（不是 `assert rc==0` 了事，要断言具体输出值）
