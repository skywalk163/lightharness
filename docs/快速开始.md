# 快速开始

本文档引导你在 5 分钟内跑通第一个 lightharness agent。

## 前置要求

| 依赖              | 版本   | 说明                                                                                  |
| --------------- | ---- | ----------------------------------------------------------------------------------- |
| Python          | 3.8+ | 运行器与光明编译器均基于 Python                                                                 |
| 光明语言（LightLang） | 最新版  | lightharness 的源码语言，编译器来自 [light-merge](https://github.com/lightlang/light-merge) 仓库 |
| Git             | 任意   | 克隆仓库                                                                                |

> lightharness 自带一份自包含 stdlib（`stdlib/` 目录），不依赖光明语言的标准库，只需编译器。

## 安装 lightharness

```bash
git clone <仓库地址> lightharness
cd lightharness
```

仓库结构：

```
lightharness/
├── 运行.py          # 运行器（编译并执行 .light 程序）
├── src/             # 核心源码（会话/代理/工具/客户端等）
├── stdlib/          # 自包含标准库
├── examples/        # 示例与测试
├── docs/            # 文档
└── tests/           # 回归测试
```

## 配置 API Key

lightharness 通过环境变量传递 API 密钥，避免与命令行参数冲突。

**Windows（PowerShell）：**

```powershell
$env:DEEPSEEK_API_KEY = "sk-你的密钥"
```

**Linux / macOS（bash）：**

```bash
export DEEPSEEK_API_KEY="sk-你的密钥"
```

支持的环境变量：

| 变量                                     | 默认值                                         | 说明       |
| -------------------------------------- | ------------------------------------------- | -------- |
| `DEEPSEEK_API_KEY` / `HARNESS_API_KEY` | （必填）                                        | API 密钥   |
| `HARNESS_ENDPOINT`                     | `https://api.deepseek.com/chat/completions` | API 端点   |
| `HARNESS_MODEL`                        | `deepseek-chat`                             | 模型名      |
| `HARNESS_ROOT`                         | `$HARNESS_HOME/legacy`（缺省 `~/.lightharness/legacy`） | 会话级设置根（`session-modes.json` / `session-models.json` / 工具根）；**会话 JSONL 与索引不在这里**，在 `$HARNESS_HOME/sessions` |
| `HARNESS_HOME`                         | `~/.lightharness`                           | 数据总目录：会话 JSONL + 索引在 `$HARNESS_HOME/sessions` |

## 第一个 Agent

创建 `examples/你好.light`：

```light
# 导入核心模块
从 客户端 导入 客户端
从 代理 导入 代理循环
从 会话 导入 新建会话
从 工具 导入 工具注册表

段落 主:
  # 1. 创建 LLM 客户端（端点/密钥/模型）
  设 客户端对象 为 新建 客户端("https://api.deepseek.com/chat/completions", 环境变量("DEEPSEEK_API_KEY"), "deepseek-chat")
  # 2. 创建会话（append-only 事件日志）
  设 会话对象 为 新建会话("demo_001", ".")
  # 3. 创建工具注册表（可注册自定义工具）
  设 注册表 为 新建 工具注册表()
  # 4. 创建代理循环并驱动一轮对话
  设 代理 为 新建 代理循环(会话对象, 客户端对象, 注册表, [])
  设 结果 为 代理.驱动("用一句话介绍光明语言")
  # 5. 打印轮次结果
  打印 "轮次结束: " 加上 结果["种类"]
```

内置工具在模型面的名字是 `<域>__<动作>` 语义线名（如 `workflow__todo_write`、`workflow__goal`、`web__search`、`web__fetch`、`shell__run`），核心 fs 四件套仍是 `read_file` / `write_file` / `search_files` / `edit_file`。旧名（`todo_write` / `web_search` / `goal` 等）仍可调用，完整映射见 README「模型面工具名（线名）」。

## 运行方式

```bash
# 运行你的第一个 agent
python 运行.py examples/你好.light

# 冒烟测试（验证自包含 stdlib，无需 API Key）
python 运行.py examples/冒烟.light

# CLI 入口（单轮，通过环境变量传消息；入口包装见 examples/运行CLI.light）
$env:HARNESS_MSG="你好"
python 运行.py examples/运行CLI.light

# CLI 交互模式（多轮对话）
$env:HARNESS_REPL="1"
python 运行.py examples/运行CLI.light
```

## 新会话落地页冒烟清单（五件事，逐条勾）

> 覆盖 T-0395~T-0399：起服务（`python 运行.py examples/运行Web服务器.light`，或你本机常用入口），
> 浏览器打开终端里打印的地址。每勾一条都记下「预期现象」；任一条不符，先按最后一列排查再报 bug。

| # | 操作 | 预期现象 | 失败时怎么排查 |
| --- | --- | --- | --- |
| 1 目录 | 点输入框上方的目录 chip，选一个**已存在**的目录（或粘贴绝对路径）；再点「新建会话」 | chip 显示该路径；`GET /api/cwd/check?工作目录=<urlencoded>` 返回 `存在/是目录/可读` 全为 `true`，`错误` 为空；会话建好后 `GET /api/sessions/<id>` 的 `工作目录` 就是它 | chip 标红 = 服务端返回 `{可读:false}`：看 `错误` 字段（原因三分：`路径不存在` / `路径存在但不是目录` / 目录遍历失败=不可读）。**建会话**时相对路径会被 400 拒（`工作目录必须是绝对路径`）；`cwd/check` 却接受相对路径并按**服务进程 cwd** 解析后回显 `绝对路径` —— 两者口径不同，别把 check 的 200 当成「能建会话」。另注意 `HARNESS_ROOT` 会强制覆盖**工具**根，与这里的**会话**目录不是一回事 |
| 2 模式 | 新会话弹层里选一个模式（`standard` / `cordis` / `ptc` / `minimal`），再创建 | 创建后 `GET /api/sessions/<id>` 的 `模式` 与所选一致；切到别的会话再切回来，下拉**自动还原**成该会话的模式 | 若为 `""` = 该会话没有会话级设置（跟随全局）。直接看持久化文件 `<根>/session-modes.json`（`<根>` = `HARNESS_ROOT`，缺省 `$HARNESS_HOME/legacy`，再缺省 `~/.lightharness/legacy`）里该会话 id 的 `模式` 键；键写成非法值会被**静默丢弃**（创建时丢弃而非报错），所以「选了没生效」先查这里有没有这个键 |
| 3 权限 | 同一弹层里选权限预设（`全放行` / `按类别` / `全拒绝` / `自定义`） | 创建后 `GET /api/sessions/<id>` 的 `权限预设` 与所选一致（四个值**都**会落库，含 `自定义`）；两会话分别设「全放行 / 全拒绝」时，同一工具在 A 放行、在 B 被拒，互不污染 | 若两个会话互相串 = 走了全局 `POST /api/permissions`（会话级应走 `POST /api/sessions/<id>/模式权限`）。`GET /api/permissions` 只反映**全局默认**，不是会话值；改全局默认不应影响已创建的会话。⚠️ 注意 `GET /api/sessions/current` 带认证令牌时会忽略 `?session=`（返回该令牌最后创建的会话），排查会话串味时**优先看 `/api/sessions/<id>`**，别拿 current 当真相 |
| 4 附件 | 先不发送，在空会话里点回形针挂 1~2 个文件（可先新建空会话再挂） | chips 列出文件名；发送成功后 chips 清空；切到**另一个**会话时 chips 清空并提示「已清空 N 个未发送的附件」；单文件 >10MB 或超过 20 个会被跳过并给出提示 | chips 不出来 = 浏览器 `FileReader` 读失败（看控制台）。发送后仍残留 = 发送失败（400/断网）时**故意保留**，重试即可。服务端当前不消费 `attachments` 字段（只保证不打断消息），附件不会进模型上下文 |
| 5 压缩 | 发几轮消息，看输入区右下角「上下文 xx%」；点「压缩」并确认 | 百分比随统计帧（`"种类":"统计"` 的 SSE 帧）回填，>80% 变黄、>95% 变红；确认后等同发一条 `/compact`（**同一条** `POST /v1/chat/completions`，没有独立端点）；压缩后**继续发消息**仍正常（会话不炸、历史可回看） | 提示「还没有进行中的会话」= 先发一条消息建立会话；提示「正在流式输出」= 等本轮结束。压缩后若继续发消息 500，记下响应体并对照 `tests/test_T0399_新会话对齐.py` 第 4 组。注意 `/compact` 只是**一条普通消息**：服务端是否真的生成摘要取决于压缩阈值（`HARNESS_COMPACTION_THRESHOLD`），所以「点了压缩但历史没变短」通常是阈值没到，不是入口坏了 |

命令行快速复核（不点 UI 也能验第 1 条）：

```bash
PORT=<端口>; TOK=<HARNESS_WEB_TOKEN>
# 只读校验，不改进程 cwd、不写 settings.json
curl -s "http://127.0.0.1:$PORT/api/cwd/check?工作目录=$(python3 -c 'import urllib.parse,sys;print(urllib.parse.quote(sys.argv[1]))' /你的/目录)"

# 建一个带目录+模式+权限的会话，再把三个键读回来（这条就是「五件事」的骨架）
curl -s -X POST "http://127.0.0.1:$PORT/api/sessions" -H "X-Auth-Token: $TOK" \
  -H 'Content-Type: application/json' \
  -d '{"标题":"冒烟","工作目录":"/你的/目录","模式":"ptc","权限预设":"全放行"}'
# 响应里的 id 拿去读详情（切回恢复看的就是这个端点）
curl -s "http://127.0.0.1:$PORT/api/sessions/<id>" -H "X-Auth-Token: $TOK"
```

> 触发工具调用，一条链验完目录/模式/权限/附件/压缩。

## 六种模式与运行中的排队/插话（T-0403 / T-0407）

预设清单（`预设清单()`）现在是 8 个 id，新建会话时 `模式` 字段与 CLI `--preset` 都按它校验：

| id | 中文名 | 一句话 |
|---|---|---|
| `standard` | 标准 | 默认四工具（bash/读/写/搜索） |
| `ptc` | PTC | 标准 + 规划工具面 |
| `minimal` | 极简 | 只给 bash |
| `cordis` | 创造 | 标准 + 扩展面 |
| `topdown` | 自上而下 | 先出计划树再按依赖执行，保留目标工具 |
| `bottomup` | 自下而上 | 无中央规划，领原子单元逐个交回，不给目标/提问工具 |
| `brainstorm` | 头脑风暴 | 只给只读工具（读/搜索），分「发散→硬闸→收敛」 |
| `lazy` | 懒人 | 决策阶梯：不做→现成服务→现成库→已有依赖→一行→才写新代码 |

- 每个模式的「触发方式 / 控制流向 / 人机介入点 / 输出形态 / 终止条件 / 实现要点」见
  **[功能对标/模式规格.md](功能对标/模式规格.md)**；brainstorm 的只读边界与装配层缺口也在那。
- 模式是**会话级**、不互斥、不跨任务；切回旧会话会恢复该会话自己的模式与权限。

运行中再发消息不会丢：

- 同一会话正忙时，普通消息返回 `202`，体里带 `排队` 位置/深度/上限；队列满返回 `429`。
- 点前端「立即插话」会带 `X-LH-Interrupt: 1`，返回 `202`（`状态:插话`）；插话优先于排队消费。
- 流式请求期间也一样：整段推流占住会话，发完自动释放；`/compact` 撞上忙碌会返回 `409`。
- 顶栏会实时显示本轮计时与 `tok/s`，轮末统计帧带 `开始时刻/完成时刻/耗时秒/速率/轮次数`。

> 排查：收到 `202` 不是失败，是排队；一直不开始就查当前轮是否卡在工具/模型调用。
> 收到 `409` 说明会话在跑，等本轮结束或改用排队。排队闸门是**每进程单例**，
> 同时起多个 `运行.py` 时各排各的，不共享队列。
