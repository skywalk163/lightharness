# 快速开始

本文档引导你在 5 分钟内跑通第一个 lightharness agent。

## 前置要求

| 依赖              | 版本   | 说明                                                                                  |
| --------------- | ---- | ----------------------------------------------------------------------------------- |
| Python          | 3.8+ | 运行器与光明编译器均基于 Python                                                                 |
| 光明语言（LightLang） | 最新版  | lightharness 的源码语言，编译器来自 [light-merge](https://github.com/lightlang/light-merge) 仓库 |
| Git             | 任意   | 克隆仓库                                                                                |

> lightharness 自带一份自包含 stdlib（`stdlib/` 目录），不依赖光明语言的标准库，只需编译器。

## 安装 lightharness

```bash
git clone <仓库地址> lightharness
cd lightharness
```

仓库结构：

```
lightharness/
├── 运行.py          # 运行器（编译并执行 .light 程序）
├── src/             # 核心源码（会话/代理/工具/客户端等）
├── stdlib/          # 自包含标准库
├── examples/        # 示例与测试
├── docs/            # 文档
└── tests/           # 回归测试
```

## 配置 API Key

lightharness 通过环境变量传递 API 密钥，避免与命令行参数冲突。

**Windows（PowerShell）：**

```powershell
$env:DEEPSEEK_API_KEY = "sk-你的密钥"
```

**Linux / macOS（bash）：**

```bash
export DEEPSEEK_API_KEY="sk-你的密钥"
```

支持的环境变量：

| 变量                                     | 默认值                                         | 说明       |
| -------------------------------------- | ------------------------------------------- | -------- |
| `DEEPSEEK_API_KEY` / `HARNESS_API_KEY` | （必填）                                        | API 密钥   |
| `HARNESS_ENDPOINT`                     | `https://api.deepseek.com/chat/completions` | API 端点   |
| `HARNESS_MODEL`                        | `deepseek-chat`                             | 模型名      |
| `HARNESS_ROOT`                         | `sessions`                                  | 会话持久化根目录 |

## 第一个 Agent

创建 `examples/你好.light`：

```light
# 导入核心模块
从 客户端 导入 客户端
从 代理 导入 代理循环
从 会话 导入 新建会话
从 工具 导入 工具注册表

段落 主:
  # 1. 创建 LLM 客户端（端点/密钥/模型）
  设 客户端对象 为 新建 客户端("https://api.deepseek.com/chat/completions", 环境变量("DEEPSEEK_API_KEY"), "deepseek-chat")
  # 2. 创建会话（append-only 事件日志）
  设 会话对象 为 新建会话("demo_001", ".")
  # 3. 创建工具注册表（可注册自定义工具）
  设 注册表 为 新建 工具注册表()
  # 4. 创建代理循环并驱动一轮对话
  设 代理 为 新建 代理循环(会话对象, 客户端对象, 注册表, [])
  设 结果 为 代理.驱动("用一句话介绍光明语言")
  # 5. 打印轮次结果
  打印 "轮次结束: " 加上 结果["种类"]
```

## 运行方式

```bash
# 运行你的第一个 agent
python 运行.py examples/你好.light

# 冒烟测试（验证自包含 stdlib，无需 API Key）
python 运行.py examples/冒烟.light

# CLI 入口（单轮，通过环境变量传消息；入口包装见 examples/运行CLI.light）
$env:HARNESS_MSG="你好"
python 运行.py examples/运行CLI.light

# CLI 交互模式（多轮对话）
$env:HARNESS_REPL="1"
python 运行.py examples/运行CLI.light
```

## 新会话落地页冒烟清单（五件事，逐条勾）

> 覆盖 T-0395~T-0399：起服务（`python 运行.py examples/运行Web服务器.light`，或你本机常用入口），
> 浏览器打开终端里打印的地址。每勾一条都记下「预期现象」；任一条不符，先按最后一列排查再报 bug。

| # | 操作 | 预期现象 | 失败时怎么排查 |
| --- | --- | --- | --- |
| 1 目录 | 点输入框上方的目录 chip，选一个**已存在**的目录（或粘贴绝对路径）；再点「新建会话」 | chip 显示该路径；`GET /api/cwd/check?工作目录=<urlencoded>` 返回 `存在/是目录/可读` 全为 `true`，`错误` 为空；首条消息后 `GET /api/sessions/current?session=<id>` 的 `工作目录` 就是它 | chip 标红 = 服务端返回 `{可读:false}`：看 `错误` 字段（不存在 / 不是目录 / 不可读）。发消息后 400 = 目录被删或写成相对路径；相对路径按**服务进程 cwd** 解析。另注意 `HARNESS_ROOT` 会强制覆盖工具根，与这里的会话目录不是一回事 |
| 2 模式 | 新会话弹层里选一个模式（`standard` / `cordis` / `ptc` / `minimal`），再创建 | 创建后 `GET /api/sessions/current` 的 `模式` 与所选一致；切到别的会话再切回来，下拉**自动还原**成该会话的模式 | 若为 `""` = 该会话没有会话级设置（跟随全局）。直接看持久化文件 `<根>/session-modes.json` 里该会话 id 的 `模式` 键；键写成非法值会被静默丢弃 |
| 3 权限 | 同一弹层里选权限预设（`全放行` / `按类别` / `全拒绝` / `自定义`；`自定义` = 暂不落库，按全局） | `GET /api/sessions/current` 的 `权限预设` 与所选一致；两会话分别设「全放行 / 全拒绝」时，同一工具在 A 放行、在 B 被拒，互不污染 | 若两个会话互相串 = 走了全局 `POST /api/permissions`（会话级应走 `POST /api/sessions/<id>/模式权限`）。`GET /api/permissions` 只反映**全局默认**，不是会话值；改全局默认不应影响已创建的会话 |
| 4 附件 | 先不发送，在空会话里点回形针挂 1~2 个文件（可先新建空会话再挂） | chips 列出文件名；发送成功后 chips 清空；切到**另一个**会话时 chips 清空并提示「已清空 N 个未发送的附件」；单文件 >10MB 或超过 20 个会被跳过并给出提示 | chips 不出来 = 浏览器 `FileReader` 读失败（看控制台）。发送后仍残留 = 发送失败（400/断网）时**故意保留**，重试即可。服务端当前不消费 `attachments` 字段（只保证不打断消息），附件不会进模型上下文 |
| 5 压缩 | 发几轮消息，看输入区右下角「上下文 xx%」；点「压缩」并确认 | 百分比随统计帧回填，>80% 变黄、>95% 变红；确认后等同发一条 `/compact`；压缩后**继续发消息**仍正常（会话不炸、历史可回看） | 提示「还没有进行中的会话」= 先发一条消息建立会话；提示「正在流式输出」= 等本轮结束。压缩后若继续发消息 500，记下响应体并对照 `tests/test_T0399_新会话对齐.py` 第 4 组 |

命令行快速复核（不点 UI 也能验第 1 条）：

```bash
# 只读校验，不改进程 cwd、不写 settings.json
curl -s "http://127.0.0.1:<端口>/api/cwd/check?工作目录=$(python -c 'import urllib.parse;print(urllib.parse.quote(r"/你的/目录"))')"
```
