## test_终端PTY.light（**已解决**：2026-08-30 硬化测试 + 删 EXPECT_RED 登记）

- **原现象（历史留痕）**：FreeBSD runner 上该用例偶发 rc=1，断言失败
  `输出应含计算结果 3，实际=expr 1 + 2`——
  PTY 会话写入 `expr 1 + 2` 后只回显了命令本身，没读到 shell 的执行结果 `3`。
- **原根因误判（已纠正）**：曾归因为「FreeBSD PTY 实现既有缺陷、平台相关」。
  但实际是**测试侧计时脆弱**——原测试用固定 `time.sleep(0.5)` + 单次 `读取(N)`，
  且只断言最后一段 delta；慢 shell / 高负载 runner 上执行结果晚于读取窗口到达，
  单段断言漏判（回显见、结果漏）。与编译器/PTY 实现无关：两轮 CI 之间
  lightharness 代码零改动，PTY 变绿的唯一变量是编译器版本（而 P0-2 不碰 `终端.light`），
  故这次红→绿属计时脆弱侥幸，非真修复。
- **真实修复（测试侧）**：`examples/test_终端PTY.light` 改用 `读至包含(会话, 标记, 预算)`
  轮询助手——循环 `读取(0.5)` 累积全文、直到命中标记或预算耗尽（读写预算 15s、
  exit 轮询 10s），断言改为对**累积全文**判含。消除固定 sleeps 与单段 delta 断言的脆弱性，
  对慢 shell / 高负载免疫。语义三段（启动/读写/持续）与结尾 `test_终端PTY PASS` 不变。
- **登记动作**：`tests/test_回归.py` 的 `EXPECT_RED` 在非 Windows 下曾包含
  `test_终端PTY.light` 作临时挡板；现**已删除**，门禁全量硬判绿
  （`EXPECT_RED` 归零，符合「EXPECT_RED 应保持为空」验收口径）。
- **与 P0-2 关系**：**无关**（同原判定，保留）。
- **验证**：本地 Windows/ConPTY 跑 `test_终端PTY.light` 稳定绿；
  b93bb23 触发 CI 时该用例已变绿并触发 EXPECT_RED 自清理断言失败 →
  本次硬化 + 删登记后，CI 应全绿。
