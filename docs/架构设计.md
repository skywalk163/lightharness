# lightharness 架构设计（光明版）

> 蓝图来源：DeepSeek Harness `docs/architecture.md`（原版）。本文把原版的 Cordis/TypeScript 概念映射到光明语言，作为 lightharness 所有 `.light` 模块的建造依据。
> 原版概念 → 光明实现 的映射是本文件的核心。

## 1. 核心概念与光明映射

| 原版概念（TS） | 说明 | 光明实现 |
|---|---|---|
| `ctx`（Cordis Context） | 插件共享的上下文容器，注册服务 | `上下文` 类：持有 会话库/工具注册表/LLM 客户端/事件总线/配置 |
| 插件（plugin） | 一切皆插件，向 ctx 贡献服务 | 模块 + `注册(上下文)` 段；用 `事件总线.light` 的订阅/发布实现 |
| `SessionEvent` 事件日志 | append-only 的持久事实日志 | `会话` 类：`事件表`（list）+ `追加(类型, 数据)` 段 + 持久化 |
| Session（会话） | 事件日志 + 内存存储 + surface 投影 | `会话` 类 + `会话/JSONL持久化.light` |
| Message（消息） | role/content/source 三要素 | `核心/消息.light`：字典结构 + 构造段 |
| Agent loop（turn/step） | 轮次 = 多个步骤；步骤 = 一次模型请求 + 工具执行 | `核心/循环.light` |
| Inbox（输入队列） | 消息按 target 入队（next-turn / next-step） | `核心/收件箱.light` |
| llm 流式词汇表 | StreamChunk / ContentBlock / FinishReason / TokenUsage | `大模型/流.light` |
| 工具注册表 + 流水线 | prepare → dispatch → finalize | `工具/注册表.light` + `工具/流水线.light` |
| 事件域 | 会话事件（持久）/ agent 事件（实时）/ 能力事件 | `核心/事件.light` 三张事件总线 |

## 2. 会话事件日志（Session Event Log）—— 核心中的核心

光明版 `会话` 类数据结构：

```
会话:
  属性 标识       # 会话 id
  属性 事件表     # [{类型, 序号, 时间, 数据}]
  属性 头部       # 版本/创建时间/cwd/父会话/种子长度
  属性 表面节点   # surface 折叠出的消息产生事件序号（模型可见序列）
```

事件类型（对齐原版 `SessionEventMap`）：
- 轮次边界：`turn/start`、`turn/end`（reason: completed/aborted/blocked/error/max-tokens/interrupted）
- 步骤边界：`step/start`、`step/end`
- 消息：`user/message`、`assistant/chunk`（原始流块）、`assistant/message`（组装后）、`tool/call`、`tool/result`
- 请求状态：`request/header`（config/system/tools 快照）、`request/context`（路由元数据）
- 其他：`todo/write`、`session/end-seed`

surface 折叠规则（对齐原版 `surface.ts`）：
- 只有 `user/message`、`assistant/message`、`tool/result` 三种事件产生 LLM 消息（surface 事件）
- 追加（append）与替换（replace，compaction 用）两种 surface 操作
- `导出消息()`：从 surface 节点逐个投影出 `消息` 列表（模型历史）

## 3. 轮次/步骤流程（Turn/Step Flow）

```
turn/start
  → 领取下一步输入（收件箱）
  → 组装系统提示 + 工具 schema
  → pre-step 决策（改写/拒绝/进入）
  → step/start
    → 追加 user/message
    → 从日志导出模型历史
    → 组装请求（request/header 变更时记录）
    → llm 流式请求：assistant/chunk* → assistant/message（含用量）
    → 若含 tool-call：工具流水线 → tool/call* → tools/pre-execute → tools/execute → tool/result*
    → 若还有欠的步骤/新输入 → 进入下一步
  → step/end
  → agent/turn-stopping（序列事件）
turn/end
```

光明实现要点：
- 循环驱动：`循环.light` 的 `驱动()` 段，内部 while 循环跑 turn；turn 内部 while 循环跑 step
- 取消：`取消令牌`（bool + 原因），步骤间检查
- 错误：max-tokens 粘滞（一旦某步触顶，整个 turn 的 reason 保持 max-tokens）；结构化失败

## 4. LLM 流式词汇表

```
内容块（ContentBlock）: text | reasoning | image | tool-call | tool-result
流块（StreamChunk）:   block-start | text-delta | reasoning-delta | tool-call-delta | block-end | usage | finish
完成原因（FinishReason）: stop | tool-calls | max-tokens | aborted | error
用量（TokenUsage）:    inputTokens / outputTokens / cacheReadTokens / cacheWriteTokens / reasoningTokens
```

光明实现：全部用字典 + `类型` 键判别。组装器（`流.light` 的 `组装器` 类）：逐块 push，收尾产出 `块表` + `完成原因` + `用量`。

## 5. 工具系统

```
工具定义: {名字, 描述, 参数模式(JSON Schema), 执行段引用, 并发模式(exclusive/parallel), 收尾段引用}
执行流水线: 准备(prepare) → 派发(dispatch) → 收尾(finalize/finish) → 追加 tool/result
并发: exclusive 串行屏障；parallel 有界滑动池（maxParallelToolCalls）
```

## 6. 事件域（三张总线）

| 事件域 | 持久性 | 用途 | 光明实现 |
|---|---|---|---|
| 会话事件 | 持久（落 JSONL） | 事实、历史重建 | `会话.追加` 直接入日志 |
| agent 事件（`agent/*`） | 实时 | inbox/状态/请求/错误 | `事件总线` 实例，随 agent 作用域 |
| 能力事件（`tools/*` 等） | 实时 | 附加策略/适配器 | `事件总线` 实例 |

waterfall（瀑布）事件：监听器必须 `下传()` 才能委托；serial 事件：无下传，按序执行。

## 7. 自包含运行约定

- `stdlib/`：自包含标准库（复制自 light-merge，`.light` + `.py` 双份）
- 光明编译器：来自 light-merge（语言本体），经 `运行.py` 引导
- 生成的 Python 自带 stdlib 引导：`<脚本目录>/../stdlib` 命中项目根的 `stdlib/`

## 8. 模块清单（P0）

| 光明模块 | 职责 | 原版对应 |
|---|---|---|
| `核心/消息.light` | 消息值类型 + 构造 | `llm/message.ts` |
| `核心/会话.light` | 会话事件日志 + surface | `core/session` |
| `核心/事件.light` | 三事件域总线 | `core/hooks` + cordis |
| `核心/上下文.light` | 服务容器（ctx） | cordis `ctx` |
| `核心/作用域.light` | 按 agent 作用域注册 | `core/scope` |
| `核心/系统提示.light` | 提示词片段 + 工具 schema 组装 | `core/system-prompt` |
| `核心/收件箱.light` | 输入队列（next-turn/next-step） | `core/agent/inbox.ts` |
| `核心/智能体.light` | Agent 接口 + 注册表 | `core/agent` |
| `核心/循环.light` | agent-loop 驱动 | `core/agent-loop/agent.ts` |
| `大模型/流.light` | 流词汇表 + 组装器 | `llm/llm` |
| `大模型/deepseek客户端.light` | deepseek 适配器（流式/工具/用量） | `llm/llm-deepseek` |
| `工具/注册表.light` | 作用域化注册 + schema | `core/tools` |
| `工具/流水线.light` | 执行流水线（prepare/dispatch/finalize） | `core/tools` + `agent-loop/tool-calls.ts` |
| `会话/JSONL持久化.light` | 事件日志 JSONL 持久化 | `session/session-persistence-jsonl` |
| `上下文/压缩.light` | surface replace 压缩 | `compaction/compaction` |
| `钩子/协议.light` | 外部 hook（claude-code/codex 兼容） | `hooks/hook-protocol` |
| `主程序.light` | CLI 入口（headless runner） | `apps/cli` + `bundle/headless` |

P1 运行层模块：`运行层/子进程.light`（subprocess）、`运行层/终端.light`（terminal）、`运行层/沙箱.light`（sandbox）、`运行层/文件.light`（fs/storage）。

## 9. 对齐判定

每模块一张功能对标卡：原版功能 → 光明实现 → 对齐度（done/partial/none）+ 证据文件 + 反跑判据 + 语言缺陷登记。见 `docs/功能对标/对标清单.json`。
