## 一、并发任务分解

### S1・轨道 A：stdlib/builtins.py 三副本收敛 — **light-merge + lightharness**

**根因（已定位，实测）**
- 三份 builtins.py 历史上各自漂移：
  - `light-merge/stdlib/builtins.py`（1574 行 / 158 函数，**主真源**）
  - `light-merge/bootstrap/release/stdlib/builtins.py`（1016 行 / 109 函数，**自举编译器打包用**，缺 49 个函数：`是数值`/判型族/文件族/二进制族等；boot 无独有**函数名**，但有 **JSON 三函数特例**——见下）
  - `lightharness/stdlib/builtins.py`（1539 行 / 154 函数，LH 运行时用；**LH 专属仅 `整数` 1 个**；main 有 5 个 LH 缺：`container_get`/`字符串全数字`/`是函数`/`是布尔`/`是数值`）
- **boot 侧 JSON 特例（不能盲整份覆盖）**：boot 副本有顶层 `import json as _duan_json_module`，`解析JSON`/`序列化JSON`/`美化JSON` 直用 Python `json`（:345-367）；main 真源对应函数是惰性 `import JSON`（:440-448），依赖 `JSON.light → JSON核心.light` 拆分——而 `bootstrap/release/stdlib/` 目录里**没有 `JSON核心.light`**。main 文件头 :29-36 明确警告过该 import 回路，JSON 三函数是**刻意**放体内 import 的。盲整份覆盖会让 boot 运行期 `import JSON` 落到缺依赖的路径。
- 后果：自举产物缺 `是数值`/判型族/文件族等近期新增内置；LH 运行时缺 `是数值` 等公共内置。⚠️ 函数名比对抓不住**函数体漂移**——LP-D-019② 的 `是数字符` 语义分叉正是函数体级漂移咬过人。

**要做**
1. **确立单一真源**：`light-merge/stdlib/builtins.py` 为唯一真源，其余两份由脚本同步生成，禁止手改。
2. **写同步脚本** `light-merge/scripts/sync_builtins.py`——**豁免名单在脚本内写成显式常量、合并算法写死**，禁止用"公共函数以真源为准"这种模糊表述办事（②）：
   ```python
   # 脚本顶部显式常量（唯一豁免权威，drift 测试 import 同一份）
   BOOT_JSON_EXEMPT = {"解析JSON", "序列化JSON", "美化JSON"}  # boot 侧专用实现
   LH_ONLY          = {"整数"}                                # LH 副本独有
   BOOT_KEEP_HEADER = "import json as _duan_json_module"      # boot 顶层必须保留的行
   ```
   - **`BOOT_JSON_EXEMPT` 规则写死**：这三个名字**两副本同名但函数体不同**（boot 直用 Python `json`；真源是惰性 `import JSON`，依赖 `JSON.light → JSON核心.light`，而 `bootstrap/release/stdlib/` 下**没有** `JSON核心.light`）。⇒ **命中 `BOOT_JSON_EXEMPT` 的函数永远从 boot 取、永不从真源取**（既不覆盖、也不删除 boot 版本）。⚠️ 这条必须显式判定——若按字面"真源为准"，会把真源的惰性 import 版覆盖进 boot，运行期 `import JSON` 落到缺失依赖 → 直接炸。
   - **`bootstrap/release/stdlib/builtins.py` 合并式**：`(真源全部函数 − BOOT_JSON_EXEMPT) ∪ (boot 的 BOOT_JSON_EXEMPT 原样) ∪ (boot 头原样)` → 补齐真源有而 boot 缺的 49 个；**boot 无独有函数名**，故豁免只需 `BOOT_JSON_EXEMPT` 一个集合。⚠️ **必须保留 boot 顶层 `BOOT_KEEP_HEADER`**（真源没有这行）——否则留存的三个 boot JSON 函数体引用 `_duan_json_module` 会 NameError。
   - **`lightharness/stdlib/builtins.py` 合并式**：`(真源全部函数 − LH_ONLY) ∪ (LH 的 LH_ONLY 原样)` → 补齐 main 有而 LH 缺的 5 个（`container_get`/`字符串全数字`/`是函数`/`是布尔`/`是数值`）。
   - 同步后打印 diff 行数摘要 + **两份豁免名单的命中情况**，exit 0；重复跑不产生 diff（幂等，铁律 8）。
   - **反例自检（脚本内置断言）**：跑完后断言 boot 副本 `解析JSON.__doc__`/函数体仍含 `_duan_json_module` 且**不含** `import JSON`；LH 副本仍含 `整数`。任一不成立 → exit 非 0，防"假同步成功"。
3. **boot 运行冒烟**：同步后在 release 环境 `import builtins.py`，调用判型族（`是数值`/`是数字`/`是数字符`/`是布尔`）+ `解析JSON('{"a":1}')`/`序列化JSON` 各一次，全部不抛且结果正确才算同步成功。⚠️ 冒烟**不能只验 import 成功**——本轮真正新增的是那 49 个函数（判型族/文件族/二进制族），须**各挑一个代表函数实调**（文件族、二进制族各一，如 `文件存在`/`读取文件` 类），确认在 release 目录的模块依赖下能真正跑通。
4. **CI 门禁挂钩**：`tests/unit/test_builtins_drift.py`——**`from scripts.sync_builtins import BOOT_JSON_EXEMPT, LH_ONLY`，与同步脚本共用同一份豁免常量**（单一权威，防两处漂移），断言强度分两级：
   - boot 副本：**公共函数（真源函数集 − `BOOT_JSON_EXEMPT`）函数体哈希一致**；`BOOT_JSON_EXEMPT` 三函数**断言取 boot 版（含 `_duan_json_module`、不含 `import JSON`）**；boot 运行冒烟兜底
   - LH 副本：函数名集合 diff == **`LH_ONLY`（==`{整数}`）**（同步后 main 缺的 5 个已补齐，post-sync 的函数名 diff 只可能是这一个）+ **公共函数规范化函数体哈希一致**（防止再出 `是数字符` 那种函数体级语义分叉）
5. **函数体级比对**用「`def 名(...):` 到下一个顶层 `def` 的文本块 strip 后哈希」，不引第三方依赖。

**验收（逐条）**
- `python scripts/sync_builtins.py` 跑通且幂等（跑两遍第二遍零 diff）。
- 自举副本 `bootstrap/release/stdlib/builtins.py` 包含 `是数值`/判型族/文件族等全部公共函数；**`BOOT_JSON_EXEMPT` 三函数（`解析JSON`/`序列化JSON`/`美化JSON`）保持 boot 直用 `json` 的实现不变，且顶层 `BOOT_KEEP_HEADER`（`import json as _duan_json_module`）保留**。
- **boot 运行冒烟通过**：判型族 + `解析JSON`/`序列化JSON` + **本轮新增家族代表函数（文件族/二进制族各一）** 在 release 环境全部可用（非仅 import 成功）。
- `tests/unit/test_builtins_drift.py` 通过。
- LH 仓 `lightharness/stdlib/builtins.py` 的 LH 专属函数 `整数` 不丢失；5 个缺失函数补齐。

**反跑判据**
- 修前：`bootstrap/release/stdlib/builtins.py` grep `是数值` 无结果（⚠️ `是数字` 在 ：677 本来就有，**别用 `是数字` 做判据**）；修后：grep 命中。

**砍线（实际合并面很小，预期用不上）**：若合并时发现 LH 副本某公共函数体内联了 LH 特定路径且语义确需分叉，则该函数**加入 `LH_ONLY` 常量**（同步脚本与 drift 测试同步生效），其余照同步。若 boot 的 `BOOT_JSON_EXEMPT` 三函数与真源冲突不可调和，则它们**永远留在 `BOOT_JSON_EXEMPT`**，不强行统一。

### S2・轨道 B：parser 中缀 `取模` 补齐 + 别名括号通用修复 + 2 个空桩测试补体 — **light-merge**

**根因（已定位，实测）**
- `tests/test_self_host_bootstrap.py` 的 `_compile_and_run`（:35-52）走 **unified 腿**（`LightCompiler` + `UnifiedCodeGenerator`）——注意**不是 SRC 腿**（SRC 腿指 `code_generator.py` 的 `PythonCodeGenerator`），标签别混。
- **`取模` 真正闸门在 parser，不在生成器**：`parser_core.py:274` `MUL_OP_MAP = {'乘':'*', '除':'/', '模':'%', '乘以':'*', '除以':'/', '模以':'%', '取余':'%', '整除':'//'}`，**唯独缺 `取模`**；`parser_expr.py:665-679` 只认这张表生成 BinaryOp。生成器的 `operator_map` 里 `'%'`/`'模'` 本来就在（`code_generator.py:291,293`、unified `:112,125`）——**给 operator_map 加 `'取模'` 是空操作，parser 根本没生成 BinaryOp 节点**。实测 `取余` 中缀 =1（在表里）、`取模` 中缀静默得 `10`（不在表里）旁证。
- **别名括号 bug 是系统性的，不止 `取模`/`整除`**：unified `:2851` `f"{func_name}({args_str})"` 在 `func_name` 已是 lambda 串时生成游离 lambda（`code_generator.py` 有同构点）。实测 unified 下 `取模(10,3)`/`整除(10,3)`/`平方(5)`/`重复(7,3)` 全部静默返回函数对象（不是数值）。只修 `取模`/`整除` 会漏掉 `平方`/`重复`/`分割`/`拼接`/`切分`/`洗牌`/`查找` 一批同类静默错误。
- `非 (...)` 顶层表达式**实测已正确**（`设 r 为 非 (1 大于 0)` → `False`），无需修编译器，只补测试体。
- `:176` `test_binary_mod` 与 `:277-280` `test_logical_not` 是**纯 `pytest.skip` 空桩，连测试代码都没有**——只删 skip 会留下空测试"空虚过绿"。
